# Каркас плагина Second Brain PKB (фаза 4)

Минимальный каркас плагина Obsidian: индекс объектов модели по YAML frontmatter и стабы двух UX-контрактов — отображаемое имя по `title` и видимость слоёв. Нормативное поведение описано в [`../docs/metamodel/10-plugin-ux-contracts.md`](../docs/metamodel/10-plugin-ux-contracts.md) (ADR-008); каркас реализует данные и API контрактов, но не подменяет интерфейс Obsidian — это фаза 5.

## Состав

| Файл | Назначение |
|---|---|
| `manifest.json` | манифест плагина: `id: second-brain-pkb`, версия `0.1.0`, `minAppVersion` |
| `versions.json` | соответствие версий плагина минимальной версии приложения (шаблон Obsidian) |
| `package.json` | скрипты сборки и dev-зависимости (TypeScript, esbuild, типы `obsidian`) |
| `tsconfig.json` | строгий режим TypeScript, `noEmit` — бандл собирает esbuild |
| `esbuild.config.mjs` | сборка `src/main.ts` → `main.js` (CommonJS, `es2020`, внешние — `obsidian` и `electron`) |
| `src/main.ts` | точка входа: класс `SecondBrainPlugin`, `onload` / `onunload`, события хранилища, команды |
| `src/types.ts` | доменные типы: слой, статус, обязательные свойства (INV-01…INV-12), запись индекса |
| `src/identity.ts` | производные идентичности: UUIDv7, `type_prefix` (INV-05), имя файла (INV-06), слой по `type` (INV-09), каноническая ссылка (INV-15) |
| `src/yaml.ts` | разбор подмножества YAML: блок frontmatter → отображение ключей и значений |
| `src/frontmatter.ts` | нормализация записи индекса: обязательные свойства, род записи, производные поля |
| `src/vault-index.ts` | индекс в памяти: доступ по `id` и по пути, полный проход и инкрементальное обновление |
| `src/display-title.ts` | стаб контракта §3: отображаемое имя, индикатор совпадения имён, признак нарушения INV-07 |
| `src/layer-visibility.ts` | стаб контракта §2: тумблеры, пресеты, состояние по умолчанию, нормализация настроек |
| `src/settings-tab.ts` | панель настроек: тумблеры слоёв, три пресета, сводка индекса, перестроение |

Модули `types`, `identity`, `yaml`, `frontmatter`, `vault-index`, `display-title` и `layer-visibility` не импортируют `obsidian` и не обращаются к хранилищу, поэтому проверяются вне приложения (раздел «Проверка»).

## Сборка

```bash
cd plugin
npm install
npm run build      # tsc -noEmit -skipLibCheck && esbuild production → main.js
```

Дополнительные скрипты: `npm run typecheck` (только проверка типов) и `npm run dev` (пересборка при изменении файлов). Требования: Node.js 18 и выше, npm 9 и выше; сборка проверена на Node.js 20.20.2. Артефакт `main.js` не коммитится — путь перечислен в [`../.gitignore`](../.gitignore).

## Установка в хранилище

Плагин не опубликован в каталоге сообщества (вне scope фазы 4), установка ручная:

1. Собрать `main.js` командой `npm run build`.
2. Скопировать `manifest.json`, `main.js` и `versions.json` в каталог `<хранилище>/.obsidian/plugins/second-brain-pkb/`:

   ```bash
   mkdir -p "<хранилище>/.obsidian/plugins/second-brain-pkb"
   cp plugin/manifest.json plugin/main.js plugin/versions.json \
     "<хранилище>/.obsidian/plugins/second-brain-pkb/"
   ```

   Вместо копирования допустим символический указатель на каталог `plugin/` — тогда пересборка не требует повторного копирования:

   ```bash
   ln -s "$(pwd)/plugin" "<хранилище>/.obsidian/plugins/second-brain-pkb"
   ```

3. Перезапустить Obsidian и включить плагин в разделе «Сторонние плагины».

## Что реализовано в iter-014

- **Индекс хранилища.** При `onload` выполняется полный проход по заметкам `.md` (`vault.getMarkdownFiles()` + `cachedRead`), запись строится по каждой заметке; доступны `getById(id)`, `getByPath(path)`, `objects()`, `objectsOfLayer(layer)`, `findByName(name)`, `titleCollisions()`, `duplicateIds()`, `stats()`. События `create`, `modify`, `delete` и `rename` обновляют индекс точечно.
- **Отображаемое имя (§3).** `getDisplayTitle(file | path)` возвращает `title` объекта модели, иначе имя файла; `getTitleIndicator(file | path)` возвращает индикатор при совпадении имён — `label` определения типа, а для определений системного слоя машинный ключ; `hasTitleError(entry)` фиксирует нарушение INV-07 (§3.5.2).
- **Видимость слоёв (§2).** `isLayerVisible(layer)` и `isFileVisible(file | path)`; состояние по умолчанию — `content` и `classification` видимы, `system` скрыт (§2.3); три канонических пресета «Только знания», «Модель», «Всё» (§2.2) доступны кнопками в настройках и командами; команда «Восстановить видимость по умолчанию» возвращает состояние §2.3. Файлы вне модели не скрываются (§2.5.3).
- **Настройки.** Состояние хранится в `data.json` плагина (`layerVisibility`, `activePreset`, `customPresets`) и в данные объектов не записывается (§2.1); при чтении недостающие поля дополняются значениями по умолчанию.

## Что не реализовано (фаза 5)

- Подмена отображаемого имени в проводнике, заголовках вкладок, поиске, quick switcher, графе, панелях ссылок и предпросмотре (§3.1): API возвращает имя, вызовы в поверхностях Obsidian не подключены.
- Фильтрация выдачи поиска и узлов графа по тумблерам (§2.4): достаточно стаба API и хранения настроек (TASK.md iter-014).
- Создание объектов из пустых ссылок (§4), нормализация ссылок и обновление alias при изменении `title` (§3.3).
- Исполнение правил валидации (`../docs/validation/`, 19 правил) и схем (`../schema/`): каркас не сообщает о нарушениях, кроме признака INV-07 в API.
- Bootstrap определений системного слоя: до него `getTitleIndicator` возвращает `undefined`, так как определения типов отсутствуют в хранилище.
- Пользовательские пресеты: хранение поддержано (`customPresets`), интерфейс редактирования не реализован.
- Пометка статуса объекта (`draft`, `deprecated`) в интерфейсе (§5 контракта).

## Границы парсера frontmatter

Парсер собственный, а не `parseYamlFrontmatter` из Obsidian API: модуль остаётся чистым и проверяемым вне приложения, а бандл не содержит стороннего кода ([`../docs/PROJECT_BRIEF.md`](../docs/PROJECT_BRIEF.md), «Ограничения»: работа офлайн, без внешних зависимостей). Поддержаны: отображения (в том числе вложенные), блочные и инлайн-списки, списки отображений вида `- key: value`, блочные скаляры `|` и `>`, строки в одинарных и двойных кавычках с экранированием, числа, логические значения, `null`, комментарии, разделители строк LF и CRLF. Не поддержаны: якоря и алиасы, теги, поточные отображения `{…}`, несколько документов в файле, символ `#` внутри блочного скаляра. Ключи с неразобранным значением возвращаются в поле `unsupported`, а запись получает `kind: "partial"`.

Запись индекса имеет один из трёх родов: `object` — все восемь обязательных свойств (INV-01…INV-12) присутствуют и имеют форму, требуемую схемой [`../schema/object.json`](../schema/object.json); `partial` — frontmatter есть, но состав или форма неполны; `plain` — frontmatter отсутствует. Равенство `aliases[0]` и `title` (INV-08), согласованность `layer` и `type` (INV-09) и соответствие имени файла (INV-06) при индексации не проверяются: это правила валидации фазы 2, их исполнение в рантайме — фаза 5. Нарушение уникальности `id` (INV-02) не исправляется: обе записи доступны по пути, `id` попадает в `duplicateIds()`, а доступ по такому `id` детерминированно возвращает запись с первым по сортировке путём.

## Проверка

- **Сборка.** `npm run build` выполняет `tsc -noEmit -skipLibCheck` и сборку esbuild: ошибок TypeScript нет, бандл `main.js` создаётся (проверено в песочнице iter-014; Node.js 20.20.2, TypeScript 5.9, esbuild 0.28, типы `obsidian` 1.14).
- **Логика вне приложения.** Чистые модули собраны отдельно (`module: CommonJS`) и проверены на 19 эталонных заметках [`../examples/README.md`](../examples/README.md): построение индекса и доступ по `id` и пути, производные идентичности (INV-01, INV-05, INV-06, INV-08, INV-09), отображаемое имя и индикатор совпадений, видимость слоёв и пресеты, разбор frontmatter, инкрементальное обновление, повтор `id` и `id` не в форме UUIDv7, разрешение 23 канонических ссылок через индекс. Проверки выполняет скрипт песочницы, который в репозиторий не входит (каталог `tools/` в [`../.gitignore`](../.gitignore)); состав и результаты — [`../docs/_workflow/iterations/iter-014/REPORT.md`](../docs/_workflow/iterations/iter-014/REPORT.md).
- **Запуск в Obsidian.** `onload`, события хранилища, панель настроек и команды требуют приложения и в песочнице не запускались: проверка вручную после установки (раздел «Установка в хранилище»).
