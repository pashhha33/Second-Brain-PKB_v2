# Каркас плагина Second Brain PKB (фаза 4)

Минимальный каркас плагина Obsidian: индекс объектов модели по YAML frontmatter, подмена отображаемого имени в проводнике и заголовках вкладок и стаб второго UX-контракта — видимости слоёв. Нормативное поведение описано в [`../docs/metamodel/10-plugin-ux-contracts.md`](../docs/metamodel/10-plugin-ux-contracts.md) (ADR-008); с iter-015 контракт §3 реализован частично — подменены проводник, заголовок вкладки и заголовок панели листа, остальные поверхности отложены (DL-053, DL-054).

Модули `types`, `identity`, `yaml`, `frontmatter`, `vault-index`, `display-title`, `layer-visibility`, `title-dom`, `explorer-title`, `leaf-title` и `title-controller` не импортируют `obsidian` в рантайме (только типы) и не обращаются к хранилищу, поэтому проверяются вне приложения (раздел «Проверка»). Obsidian-слой — `main.ts` и `settings-tab.ts`.

## Сборка

```bash
cd plugin
npm install
npm run build      # tsc -noEmit -skipLibCheck && esbuild production → main.js
```

Дополнительные скрипты: `npm run typecheck` (только проверка типов) и `npm run dev` (пересборка при изменении файлов). Требования: Node.js 18 и выше, npm 9 и выше; сборка проверена на Node.js 20.20.2. Артефакт `main.js` не коммитится — путь перечислен в [`../.gitignore`](../.gitignore).

## Установка в хранилище

Плагин не опубликован в каталоге сообщества (вне scope фазы 4), установка ручная:

1. Собрать `main.js` командой `npm run build`.
2. Скопировать `manifest.json`, `main.js`, `versions.json` и `styles.css` в каталог `<хранилище>/.obsidian/plugins/second-brain-pkb/`:

   ```bash
   mkdir -p "<хранилище>/.obsidian/plugins/second-brain-pkb"
   cp plugin/manifest.json plugin/main.js plugin/versions.json plugin/styles.css \
     "<хранилище>/.obsidian/plugins/second-brain-pkb/"
   ```

   Вместо копирования допустим символический указатель на каталог `plugin/` — тогда пересборка не требует повторного копирования:

   ```bash
   ln -s "$(pwd)/plugin" "<хранилище>/.obsidian/plugins/second-brain-pkb"
   ```

   Без `styles.css` подмена имени работает, но пометка о нарушении INV-07 (§3.5.2) остаётся без оформления.

3. Перезапустить Obsidian и включить плагин в разделе «Сторонние плагины».

## Как проверить в Obsidian на `examples/`

Набор [`../examples/README.md`](../examples/README.md) — 19 эталонных заметок: 14 объектов слоя наполнения, 2 классификации и 3 системных, а также `README.md` без frontmatter (файл вне модели, §3.5.1). Шаги проверки подмены имени (§3, DoD iter-015):

1. Открыть хранилище, в котором лежат заметки `examples/` (достаточно скопировать каталог в тестовое хранилище), установить и включить плагин (раздел «Установка в хранилище»).
2. Открыть проводник файлов: вместо `note_01a17d3b-6b10-7d52-9a34-1e7c42b8f056` видно «Конспект книги How to Take Smart Notes», вместо `book_01a17d3b-6b21-7d4e-8a1c-2e4f6a8b0c13` — «How to Take Smart Notes». Файл `examples/README.md` остаётся с именем файла: он вне модели (§3.5.1).
3. Открыть заметку: заголовок вкладки и заголовок панели показывают `title`. Переключиться между вкладками, прокрутить проводник, сменить тему или сортировку — подменённое имя сохраняется (повторное применение выполняет наблюдатель, DL-054).
4. В настройках плагина («Second Brain PKB») выключить тумблер «Подменять имя на title»: проводник и вкладки возвращаются к именам файлов, состояние, близкое к stock Obsidian (DoD 3). Включить обратно — имена снова подменяются без перезапуска. Строка «Состояние подмены» показывает число затронутых элементов и наблюдателей.
5. Изменить `title` в frontmatter открытой заметки и сохранить: имя в проводнике и во вкладке обновляется (событие `modify` обновляет индекс, подмена переприменяется). Переименовать файл средствами Obsidian: `id` и ссылки не меняются, отображаемое имя остаётся `title` (§3.2, INV-06).
6. Проверить нарушение INV-07 (§3.5.2): во временной заметке с полным frontmatter удалить ключ `title` — строка проводника показывает имя файла с пунктирным подчёркиванием, знаком `⚠` и подсказкой «Нарушение INV-07…». В `examples/` таких заметок нет: все 19 объектов корректны.
7. Если имя не обновилось после внешнего изменения файлов, выполнить команду «Обновить отображаемые имена» (`refresh-display-titles`) из палитры команд.

В песочнице Obsidian не запускается, поэтому шаги 2–7 в итерации не выполнены: они описаны для ручной приёмки владельцем. Офлайн-проверки той же логики — в разделе «Проверка».

## Что реализовано в iter-015

- **Подмена отображаемого имени (§3.1, пункт 2).** Строки проводника файлов, заголовок вкладки и заголовок панели листа показывают `title` объекта модели. Источники элементов проводника: `fileItems` (Obsidian до 1.7), `treeView.itemMap` / `treeView.items` (более новые версии), запасной путь — DOM по атрибуту `data-path`. Заголовок вкладки находится по индексу листа среди соседей группы, а текст вкладки дополнительно подменён в `getDisplayText()` представления, поэтому перерисовка не возвращает имя файла (DL-054).
- **Feature-flag «Подменять имя на title».** Тумблер в настройках плагина, по умолчанию включён; состояние — в `data.json` плагина (`displayTitle.override`), настройки iter-014 без этого ключа читаются как «включено». Выключение возвращает исходные имена и снимает пометки.
- **Обратимость.** Исходный текст и исходная подсказка элемента хранятся в атрибутах `data-sbpk-original-title` и `data-sbpk-original-tooltip`, признак подмены — `data-sbpk-title`. При выключении настройки и при `onunload` тексты возвращаются, пометки и обёртки снимаются, наблюдатели отключаются.
- **Устойчивость к изменению данных.** События хранилища `create`, `modify`, `delete`, `rename` обновляют индекс (iter-014), а события раскладки `layout-change`, `active-leaf-change` и `file-open` переприменяют подмену; наблюдатель за поддеревом проводника повторяет подмену после перерисовки с дебаунсом 120 мс. Повторный проход идемпотентен: текст записывается только при отличии от текущего.
- **Пометка нарушения INV-07 (§3.5.2).** Объект модели без `title` отображается именем файла с классом `sbpk-title-error` и подсказкой; оформление — `styles.css`. Файлы вне модели (§3.5.1) и записи `partial` не подменяются и не помечаются.
- **Диагностика.** Команда «Обновить отображаемые имена» (`refresh-display-titles`) сообщает число целей до и после прохода; строка «Состояние подмены» в настройках показывает элементы проводника, наблюдателей, заголовки и обёртки.

Файл не переименовывается, содержимое заметки подменой не изменяется, ссылки и `defined_by` продолжают использовать имя файла и `id` (§3.2, INV-03, INV-06). Публичные методы Obsidian не переопределяются на уровне прототипов: запись идёт в элементы интерфейса, обёртка `getDisplayText()` ставится на экземпляре представления и снимается при выгрузке.

## Что реализовано в iter-014

- **Индекс хранилища.** При `onload` выполняется полный проход по заметкам `.md` (`vault.getMarkdownFiles()` + `cachedRead`), запись строится по каждой заметке; доступны `getById(id)`, `getByPath(path)`, `objects()`, `objectsOfLayer(layer)`, `findByName(name)`, `titleCollisions()`, `duplicateIds()`, `stats()`.
- **Отображаемое имя (§3).** `getDisplayTitle(file | path)` возвращает `title` объекта модели, иначе имя файла; `getTitleIndicator(file | path)` возвращает индикатор при совпадении имён — `label` определения типа, а для определений системного слоя машинный ключ; `hasTitleError(entry)` фиксирует нарушение INV-07 (§3.5.2).
- **Видимость слоёв (§2).** `isLayerVisible(layer)` и `isFileVisible(file | path)`; состояние по умолчанию — `content` и `classification` видимы, `system` скрыт (§2.3); три канонических пресета «Только знания», «Модель», «Всё» (§2.2) доступны кнопками в настройках и командами; команда «Восстановить видимость по умолчанию» возвращает состояние §2.3. Файлы вне модели не скрываются (§2.5.3).
- **Настройки.** Состояние хранится в `data.json` плагина (`layerVisibility`, `activePreset`, `customPresets`, с iter-015 — `displayTitle`) и в данные объектов не записывается (§2.1); при чтении недостающие поля дополняются значениями по умолчанию.

## Что не реализовано (фаза 5)

- Подмена отображаемого имени в оставшихся поверхностях §3.1: заголовок заметки (`.inline-title`), результаты поиска, quick switcher, подписи узлов графа, панели обратных и исходящих ссылок, всплывающий предпросмотр, поле значения свойства-ссылки в форме (DL-053).
- Индикатор совпадения `title` (§3.4): API готово (`getTitleIndicator`, `collisionIndicators`), но до bootstrap определений системного слоя возвращает `undefined`, поэтому в интерфейсе не выводится.
- Обновление alias в ссылках при изменении `title` (§3.3) и создание объектов из пустых ссылок (§4).
- Фильтрация выдачи поиска и узлов графа по тумблерам (§2.4): достаточно стаба API и хранения настроек (TASK.md iter-014).
- Исполнение правил валидации (`../docs/validation/`, 19 правил) и схем (`../schema/`): каркас не сообщает о нарушениях, кроме пометки INV-07 в проводнике и вкладках.
- Пользовательские пресеты: хранение поддержано (`customPresets`), интерфейс редактирования не реализован.
- Пометка статуса объекта (`draft`, `deprecated`) в интерфейсе (§5 контракта).

## Границы парсера frontmatter

Парсер собственный, а не `parseYamlFrontmatter` из Obsidian API: модуль остаётся чистым и проверяемым вне приложения, а бандл не содержит стороннего кода ([`../docs/PROJECT_BRIEF.md`](../docs/PROJECT_BRIEF.md), «Ограничения»: работа офлайн, без внешних зависимостей). Поддержаны: отображения (в том числе вложенные), блочные и инлайн-списки, списки отображений вида `- key: value`, блочные скаляры `|` и `>`, строки в одинарных и двойных кавычках с экранированием, числа, логические значения, `null`, комментарии, разделители строк LF и CRLF. Не поддержаны: якоря и алиасы, теги, поточные отображения `{…}`, несколько документов в файле, символ `#` внутри блочного скаляра. Ключи с неразобранным значением возвращаются в поле `unsupported`, а запись получает `kind: "partial"`.

Запись индекса имеет один из трёх родов: `object` — все восемь обязательных свойств (INV-01…INV-12) присутствуют и имеют форму, требуемую схемой [`../schema/object.json`](../schema/object.json); `partial` — frontmatter есть, но состав или форма неполны; `plain` — frontmatter отсутствует. Равенство `aliases[0]` и `title` (INV-08), согласованность `layer` и `type` (INV-09) и соответствие имени файла (INV-06) при индексации не проверяются: это правила валидации фазы 2, их исполнение в рантайме — фаза 5. Нарушение уникальности `id` (INV-02) не исправляется: обе записи доступны по пути, `id` попадает в `duplicateIds()`, а доступ по такому `id` детерминированно возвращает запись с первым по сортировке путём.

## Проверка

- **Сборка.** `npm run build` выполняет `tsc -noEmit -skipLibCheck` и сборку esbuild: ошибок TypeScript нет, бандл `main.js` создаётся (проверено в песочнице iter-015; Node.js 20.20.2, TypeScript 5.9, esbuild 0.28, типы `obsidian` 1.14).
- **Логика вне приложения.** Чистые модули собраны отдельно (`module: CommonJS`, `tools/tsconfig.harness.json`) и проверены на 19 эталонных заметках [`../examples/README.md`](../examples/README.md). Четыре харнесса в каталоге [`../tools/`](../tools/): `plugin_harness.cjs` — 104 проверки (индекс, отображаемое имя, видимость слоёв, разбор frontmatter, инкрементальное обновление, производные идентичности); `title-logic-harness.cjs` — 36 проверок решения о подмене и feature-flag (§3.5, группа G); `title-surface-harness.cjs` — 68 проверок операций над элементом и проводника на модели DOM (`tools/dom-model.cjs`, группа H); `title-leaf-harness.cjs` — 60 проверок вкладок, обёртки `getDisplayText()` и контроллера на фейковом приложении (группа I). Итого **268 проверок, ошибок нет**. Состав и результаты — [`../docs/_workflow/iterations/iter-015/REPORT.md`](../docs/_workflow/iterations/iter-015/REPORT.md).
- **Модель DOM вместо приложения.** Группы H и I выполняются на модели элементов (`textContent`, атрибуты, `classList`, `MutationObserver`): они подтверждают алгоритм — идемпотентность, обратимость, поиск целей, корреляцию вкладок, — но не совместимость с реальной разметкой Obsidian. Селекторы (`.nav-file-title`, `.tree-item-self`, `.workspace-tab-header-inner-title`, `.view-header-title`) взяты из публичной разметки приложения и проверяются только вручную (раздел «Как проверить в Obsidian на `examples/`»).
- **Запуск в Obsidian.** `onload`, события хранилища и раскладки, панель настроек, команды и подмена в реальном интерфейсе требуют приложения и в песочнице не запускались: проверка вручную после установки. На мобильном устройстве не проверялось; используются DOM, `MutationObserver` и `setTimeout`, `isDesktopOnly: false` сохранён.
