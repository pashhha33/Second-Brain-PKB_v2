## Состояние
Метамодель описана на уровне документов и дополнена механизмом переиспользования наборов полей, моделью изображений, стартовым набором свойств и механизмом развёртывания полей. Три слоя (`system`, `classification`, `content`), десять встроенных метатипов с фиксированными UUIDv7 (в iter-006 добавлен `field-expansion`), реестр свойств с парой **key / label**, канонический набор из четырнадцати `value_type` (включая `media` и `list<media>`), четыре отношения классификации и четырнадцать отношений ядра (в iter-006 добавлено `narrator`), каноническая форма внутренней ссылки `[[{{type_prefix}}_{{id}}|{{title}}]]`, значения фасетов как объекты `facet-value`, процедура поведения при `status: deprecated`. Наследование типов — одиночное линейное: `extends` (`0..1`, каноническая ссылка), `excludes`, `field_order`, разрешение nearest wins, запрет циклов, детерминированный порядок представления полей. Ядро типов — 29 определений в пяти группах (Знания, Контекст, Медиа, Коллекции, Действия) с пятью цепочками наследования; `image` — обёртка над файлом изображения с обязательным `attachment`; свойства ядра — 23 определения с фиксированными `id`, из них три — свойства-триггеры (`occupation`, `format`, `creation-method`). Состав полей экземпляра вычисляется: базовый набор типа (с учётом `extends` / `excludes` / `field_order`) объединяется с полями активных правил развёртывания (`type: field-expansion`, `mode: union`); значения развёрнутых полей при деактивации правила не удаляются, а становятся неактивными (INV-25…INV-27, ADR-006). Инварианты — INV-01…INV-27, реестр разделён на `01-invariants.md` (универсальные INV-01…INV-12, порядок контроля) и `09-structural-invariants.md` (структурные INV-13…INV-27) по R-006 (ADR-007, DL-030). Нормативный реестр свойств и отношений разделён на `04-properties.md` и `06-relations.md` (ADR-005, DL-022). Далее — фаза 2: перенос инвариантов и реестров в JSON Schema и правила валидации.

## Открытые хвосты
- **`08-field-expansion.md` — 259 строк**: приближается к границе R-006 (~300). Следующее расширение механизма (новые режимы `mode`, новые триггеры, примеры) требует остановки и вопроса о разбиении. `05-core-types.md` — 235 строк, `02-layers.md` — 217 строк, `04-properties.md` — 213 строк: запас есть. `01-invariants.md` после разбиения — 205 строк.
- **Триггеров три, и это ограничение первой версии** (TASK iter-006): `occupation`, `format`, `creation-method`. Потребность в новых триггерах (`language`, `license`, `status` задачи и др.) — вопрос следующих итераций, а не доработка этой.
- **Режимы `mode` кроме `union` не определены** (ADR-006, S3, А5; DL-028): в v1 `mode` принимает единственное значение `union`, режимы `first-match` и `override` отклонены и не нормативны. Введение нового режима — через ADR.
- **Активность поля не хранится явно**: неактивное при деактивации правила значение остаётся в данных и определяется как неактивное только вычислением эффективного набора полей (INV-27). Отдельное свойство-маркер или история изменений не вводились — вопрос фазы 2 (валидация) или интерфейса.
- Машиночитаемые артефакты отсутствуют: JSON Schema и правила валидации — фаза 2 (`schema/`, `docs/validation/`). Реестры подготовлены к переносу: `property_key` → имя поля, `value_type` → тип (14 значений), `enum_values` → перечисление, `required` / `applies_to` / `cardinality` → ограничения, `extends` / `excludes` / `field_order` → вычисление базового набора полей, `applies_to_type` / `trigger_property` / `trigger_values` / `adds_properties` / `adds_relations` / `mode` → вычисление эффективного набора полей, `media` → формат ссылки с ограничением цели (`type: image`).
- **Существование файла по пути `attachment` инвариантом не проверяется** (INV-24 фиксирует только обязательность ключа): проверка — кандидат в правила валидации фазы 2. Аналогично не проверяется принадлежность значения `trigger_values` к `enum_values` свойства-триггера на уровне данных (INV-25 требует согласованности определений) — кандидат в правила фазы 2.
- **Роли `book` не хранятся полем** (DL-024): роль выводится из состава данных (`attachment`, входящие `chapter-of`), поэтому интерфейс может показать её только как вычисляемую подпись. Формат книги (`format`) теперь — свойство-триггер, и роль «аудиокнига» может выводиться также из него; согласование двух механизмов вывода — вопрос интерфейса.
- **Свойства пользовательских типов не фиксируются реестром**: реестр свойств ядра (`07-core-properties.md`) покрывает стартовый набор; состав полей типов, создаваемых владельцем, остаётся его решением. Правила развёртывания для пользовательских типов допустимы (INV-25 не ограничивает тип), но примеров в документации нет.
- **Переопределение параметров унаследованного поля на уровне типа не введено** (ADR-004, I3): `value_type`, `required`, `cardinality` едины для всех типов. Ужесточение требования у потомка — отдельным свойством или правилом валидации. Возврат к вопросу при появлении потребности (вопрос 3 REPORT.md iter-004).
- Ядровые типы и правила развёртывания не имеют фиксированных `id` (DL-019), поэтому документация не может ссылаться на конкретные объекты типов ядра и правил; bootstrap ядра (29 типов, 14 отношений, 23 свойства) — опция плагина (фазы 4–5).
- Отношение «объект → домен» по-прежнему не вводится: домен объекта выводится из `category-domain` его категорий (`06-relations.md`, раздел 2, правило 3).
- Примерные `id` в YAML-примерах (значение фасета из iter-003, экземпляр книги из iter-004, обёртка `image` из iter-005, правила развёртывания из iter-006) не являются реестровыми; правило зафиксировано разделом «Иллюстративные `id` в примерах» в `03-builtin-types.md` (вопрос 8 iter-005, вариант C). Коллизий с реестровыми `id` нет.
- `docs/_workflow/OPEN_QUESTIONS.md` обновляется Оркестратором нерегулярно: в реестре три записи (Q-001 отложен, Q-002 решён → DL-021, Q-003 отложен), тогда как часть вопросов агента из REPORT.md iter-002…iter-005 статусов не получила.
- Пометки `черновик` у терминов Automation и Validation rule сохраняются до появления реестра правил валидации (фаза 2). Термин Field expansion введён без пометки, но механизм проверен только на трёх примерах.
- Q-001 (статусы фаз в `docs/PROJECT_BRIEF.md`) остаётся отложенным: триггер не сработал, файл не менялся.
