## Состояние
Метамодель описана на уровне документов: реестры типов, свойств и отношений, механизм наследования, развёртывание полей и поведение интерфейса. Три слоя (`system`, `classification`, `content`), десять встроенных метатипов с фиксированными UUIDv7, реестр свойств с парой **key / label**, канонический набор из четырнадцати `value_type` (включая `media` и `list<media>`), четыре отношения классификации и четырнадцать отношений ядра, каноническая форма внутренней ссылки `[[{{type_prefix}}_{{id}}|{{title}}]]`, значения фасетов как объекты `facet-value`, процедура поведения при `status: deprecated`. Наследование типов — одиночное линейное: `extends` (`0..1`, каноническая ссылка), `excludes`, `field_order`, разрешение nearest wins, запрет циклов, детерминированный порядок представления полей. Ядро типов — 29 определений в пяти группах (Знания, Контекст, Медиа, Коллекции, Действия); свойства ядра — 23 определения с фиксированными `id`, из них три — свойства-триггеры (`occupation`, `format`, `creation-method`). Состав полей экземпляра вычисляется: базовый набор типа объединяется с полями активных правил развёртывания (`type: field-expansion`, `mode: union`); значения развёрнутых полей при деактивации правила не удаляются, а становятся неактивными (INV-25…INV-27). Инварианты — INV-01…INV-27 в двух файлах: `01-invariants.md` (универсальные INV-01…INV-12) и `09-structural-invariants.md` (структурные INV-13…INV-27). Поведение будущего плагина зафиксировано тремя контрактами (`10-plugin-ux-contracts.md`, ADR-008): видимость слоёв — три тумблера и три пресета, по умолчанию `content` и `classification` видимы, `system` скрыт, фильтрация действует в поиске и графе, проводник и quick switcher показывают всё; отображаемое имя — `title` вместо имени файла, подмена встроена в плагин (без зависимости от Front Matter Title), файл не переименовывается; создание из пустых ссылок — по явной команде, тип определяется контекстом свойства или отношения (`target_type`), создаваемый объект получает `status: draft` и каноническую ссылку. Далее — фаза 2: перенос инвариантов и реестров в JSON Schema и правила валидации.

## Открытые хвосты
- **UX-контракты не реализованы**: `10-plugin-ux-contracts.md` фиксирует поведение для фаз 4–5, кода нет (`plugin/` пуст). Соответствие контракту проверяется при приёмке фазы 5; отклонение — только через ADR.
- **Фильтрация слоёв не действует в проводнике и quick switcher** (решение человека, iter-007; ADR-008, А1): перечень поверхностей в TASK.md iter-007 включал explorer и switcher, контракт описывает их поведение явно как «не фильтруются». Расхождение с заданием зафиксировано в REPORT.md iter-007 (отклонение 1, вопрос 1).
- **Свойства `media` / `list<media>` не описаны в контракте создания из пустых ссылок** (решение человека, iter-007): создание обёртки `image` регулируется `06-relations.md`, раздел 5, пункт 10 и INV-24, а общее правило 4.2 (единственный допустимый `target_type`) формально применимо и к `media`. Неопределённость закрыть в фазе 4 или дополнением контракта (вопрос 3 REPORT.md iter-007).
- **Подмена отображаемого имени действует только внутри плагина**: в веб-экспорте, сторонних приложениях и «голом» Markdown видно имя файла с UUID; компенсация — `title` в `aliases[0]` (INV-08) и в alias канонической ссылки (INV-15).
- **Пресеты видимости живут в настройках плагина, а не в модели**: при переустановке плагина пользовательские пресеты теряются, канонические три доступны всегда. Объектами модели пресеты не являются (DL-031).
- **`status: draft` у объектов, созданных из пустых ссылок**, требует от владельца явного перевода в `accepted` (INV-10, DL-011); массовой команды перевода статуса в контракте нет.
- **`08-field-expansion.md` — 259 строк**: у границы R-006 (~300). Расширение механизма (новые режимы `mode`, новые триггеры, примеры) требует остановки и вопроса о разбиении. `05-core-types.md` — 235 строк, `04-properties.md` — 213 строк, `02-layers.md` — 217 строк: запас есть. `10-plugin-ux-contracts.md` — 176 строк.
- **Триггеров три, и это ограничение первой версии** (TASK iter-006): `occupation`, `format`, `creation-method`. Новые триггеры — вопрос следующих итераций.
- **Режимы `mode` кроме `union` не определены** (ADR-006, S3, А5; DL-028): `first-match` и `override` отклонены и не нормативны; введение нового режима — через ADR.
- **Активность поля не хранится явно**: неактивное значение остаётся в данных и определяется только вычислением эффективного набора полей (INV-27). Маркер или история изменений не вводились.
- Машиночитаемые артефакты отсутствуют: JSON Schema и правила валидации — фаза 2 (`schema/`, `docs/validation/`). Реестры подготовлены к переносу: `property_key` → имя поля, `value_type` → тип (14 значений), `enum_values` → перечисление, `required` / `applies_to` / `cardinality` → ограничения, `extends` / `excludes` / `field_order` → базовый набор полей, `applies_to_type` / `trigger_property` / `trigger_values` / `adds_properties` / `adds_relations` / `mode` → эффективный набор полей, `layer` → фильтрация видимости, `target_type` → выбор типа при создании из пустой ссылки.
- **Существование файла по пути `attachment` инвариантом не проверяется** (INV-24); согласованность `trigger_values` с `enum_values` триггера на уровне данных (INV-25) тоже: оба — кандидаты в правила валидации фазы 2.
- **Роли `book` не хранятся полем** (DL-024): роль выводится из состава данных, а формат книги — свойство-триггер `format`; два механизма вывода должны согласовываться интерфейсом (вопрос 7 REPORT.md iter-006, без статуса).
- **Свойства пользовательских типов не фиксируются реестром**: реестр свойств ядра покрывает стартовый набор; правила развёртывания для пользовательских типов допустимы (INV-25), примеров в документации нет.
- **Переопределение параметров унаследованного поля на уровне типа не введено** (ADR-004, I3; Q-003): `value_type`, `required`, `cardinality` едины для всех типов. Кейс iter-006 — обязательность развёрнутого поля (`prompt`, `seed` при `creation-method: ai-generated`); правило развёртывания параметры полей не переопределяет (`08-field-expansion.md`, раздел 2, правило 5).
- Ядровые типы и правила развёртывания не имеют фиксированных `id` (DL-019); bootstrap ядра (29 типов, 14 отношений, 23 свойства) — опция плагина (фазы 4–5).
- Отношение «объект → домен» не вводится: домен выводится из `category-domain` его категорий (`06-relations.md`, раздел 2, правило 3).
- Примерные `id` в YAML-примерах не являются реестровыми; правило зафиксировано разделом «Иллюстративные `id` в примерах» в `03-builtin-types.md`.
- `docs/_workflow/OPEN_QUESTIONS.md` в коммите A iter-007 сведён к трём строкам-заглушкам (`Q-001 … ОТЛОЖЕНО`, `Q-002 … РЕШЕНО (DL-021)`, `Q-003 … ОТЛОЖЕНО`): триггеры и формулировки потеряны, статусов по 13 вопросам REPORT.md iter-006 нет. Файл ведёт Оркестратор (коммит A), агентом не правится.
- **Статусы фаз в `docs/PROJECT_BRIEF.md` не синхронизированы** (Q-001): фаза 0 значится «в работе», фаза 1 — «не начата», тогда как фаза 0 завершена в iter-000, а фаза 1 выполняется седьмую итерацию. Файл вне scope итераций, триггер Q-001 — его изменение.
- Пометки `черновик` у терминов Automation и Validation rule сохраняются до появления реестра правил валидации (фаза 2).
