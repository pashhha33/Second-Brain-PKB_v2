**Индекс и нормализация** (DL-051): `VaultIndex` строится полным проходом по `vault.getMarkdownFiles()` при `onload` и поддерживается событиями `create`, `modify`, `delete`, `rename`; доступ по `id` и по `path`, `duplicateIds()` перечисляет повторения `id` (INV-02), а доступ по такому `id` детерминированно возвращает запись с первым по сортировке путём — данные не исправляются. Запись индекса имеет род `object` (все восемь обязательных свойств INV-01…INV-12 присутствуют и имеют форму, требуемую `schema/object.json`), `partial` (frontmatter есть, состав или форма неполны; список недостающих ключей — в `missing`) или `plain` (frontmatter отсутствует). Нормализация (`normalizeEntry`) заполняет минимум полей инвариантов — `id`, `type`, `title`, `aliases`, `layer`, `status`, `owner` при наличии, а также `definedBy`, `typePrefix` (INV-05), `machineKey` (первое из `type_value`, `property_key`, `relation_key`, `rule_key`), `expectedLayer` как диагностику расхождения `layer` и `type` (INV-09) и `unsupported` — ключи, которые парсер не разобрал; значения не додумываются и значением по умолчанию не подменяются. Парсер YAML собственный (`parseYamlSubset`), без внешних библиотек: блочные и вложенные отображения, блочные и инлайн-списки, списки отображений, блочные скаляры `|` и `>`, кавычки с экранированием, числа, логические значения, `null`, комментарии, LF и CRLF; якоря, теги, поточные отображения `{…}` и многодокументные файлы не поддержаны. Равенство `aliases[0]` и `title` (INV-08), согласованность `layer` и `type` (INV-09) и соответствие имени файла (INV-06) при индексации не проверяются — это правила фазы 2, их исполнение в рантайме относится к фазе 5.

**Отображаемое имя и видимость слоёв**: `getDisplayTitle(file | path)` возвращает `title` объекта из индекса, иначе имя файла без расширения (§3.5); `hasTitleError` отмечает отсутствие или недопустимость `title` (§3.5.2); `getTitleIndicator` возвращает `label` определения типа, для системного слоя — машинный ключ (§3.4), а до bootstrap определений — `undefined`; `collisionIndicators` готовит диагностику совпадений индикаторов. `isLayerVisible(layer)` и `isEntryVisible(entry)` работают по трём тумблерам (§2.1); значения по умолчанию — `content` и `classification` видимы, `system` скрыт (§2.3); три канонических пресета «Только знания», «Модель», «Всё» (§2.2) плюс хранение пользовательских (`customPresets`), `matchingPreset` определяет активный пресет после ручного переключения тумблера, `normalizeSettings` приводит загруженные настройки к допустимой форме. Состояние живёт в `data.json` плагина, а не в данных заметок (DL-031); видимость влияет только на API каркаса — файлы вне модели не скрываются (§2.5.3), скрытие не выводит объект из модели (§2.5.4). Интерфейс: вкладка настроек и шесть команд — `rebuild-index`, `reset-layer-visibility`, три `apply-preset-*` и `refresh-display-titles` (iter-015).

**Подмена отображаемого имени** (iter-015, DL-053, DL-054): `title` объекта модели показывается вместо имени файла в трёх элементах интерфейса — строка проводника файлов, заголовок вкладки и заголовок панели листа (`view-header-title`). Решение о подмене принимает чистый модуль `display-title.ts` (`overrideTitleOf`, `titleErrorNote`), резолвер строится фабрикой `createTitleResolver(getEntry, getSettings)`, поверхности координирует `TitleController` (`setEnabled` / `refresh` / `detach` / `stats`). Элементы проводника берутся из `fileItems` (Obsidian до 1.7), `treeView.itemMap` / `treeView.items` (более новые версии) или из DOM по атрибуту `data-path`; заголовок вкладки находится по индексу листа среди соседей группы, а текст вкладки дополнительно подменяется обёрткой `getDisplayText()` экземпляра представления. Повторное применение после перерисовки выполняет `MutationObserver` на контейнере проводника с дебаунсом 120 мс; подмену переприменяют события `layout-change`, `active-leaf-change`, `file-open` и проход после обновления индекса (события хранилища `create`, `modify`, `delete`, `rename` обновляют индекс с iter-014). Подмена обратима: исходный текст и исходная подсказка хранятся в атрибутах `data-sbpk-original-title` и `data-sbpk-original-tooltip`, признак подмены — `data-sbpk-title`; при выключении настройки и при `onunload` тексты возвращаются, пометки и обёртки снимаются, наблюдатели отключаются (DoD 3). Границы §3.5: подменяются только записи рода `object`; файлы вне модели и `partial` остаются с именем файла; объект модели без `title` (нарушение INV-07, §3.5.2) показывается именем файла с классом `sbpk-title-error` и подсказкой; если `title` совпадает с именем файла, элемент не трогается. Файл не переименовывается и содержимое заметки не изменяется (§3.2, INV-03, INV-06). Настройка «Подменять имя на title» по умолчанию включена, состояние — в `data.json` плагина (`displayTitle.override`), настройки iter-014 без ключа читаются как «включено»; добавлены команда «Обновить отображаемые имена» (`refresh-display-titles`) и строка «Состояние подмены» в панели настроек.
