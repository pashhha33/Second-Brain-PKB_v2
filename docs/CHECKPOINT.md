## Состояние
Метамодель фазы 1 сохранена без изменений: три слоя (`system`, `classification`, `content`), десять встроенных метатипов с фиксированными UUIDv7, реестр свойств с парой **key / label**, четырнадцать `value_type`, четыре отношения классификации и четырнадцать отношений ядра, каноническая ссылка `[[{{type_prefix}}_{{id}}|{{title}}]]`, ядро из 29 типов и 23 свойств, наследование `extends` / `excludes` / `field_order` с nearest wins, развёртывание полей (`type: field-expansion`, `mode: union`), инварианты INV-01…INV-27 в двух файлах и три UX-контракта плагина.

С iter-009 у модели появилось машиночитаемое выражение первой волны. **Граница контроля** (DL-036, ADR-009, S1): JSON Schema проверяет форму одного объекта — документ, полученный из YAML frontmatter одной заметки (присутствие и форма ключей, допустимость значений, условные зависимости внутри объекта: `value_type: enum` ⇒ `enum_values`, значение `type` ⇒ значение `layer`); правило валидации как объект `type: validation-rule` проверяет всё, что требует имени файла, другого объекта, множества объектов или вычисления. Проверка, выразимая схемой, в правилах не дублируется (осознанное исключение — `image-has-attachment`); вычисления (эффективный набор полей INV-20, INV-26) не проверяются ни схемой, ни правилами — это алгоритм плагина фаз 4–5.

**Схемы** (DL-037): JSON Schema 2020-12, `$id` — относительное имя файла, `$ref` — по именам файлов и указателям `#/$defs/…`, внешних URL кроме идентификатора версии нет; один файл — один класс объектов, выбор схемы — по значению `type`. Три файла: `object.json` (восемь обязательных свойств, UUIDv7, kebab-case, непустые `title` / `aliases` / `owner`, наборы `layer` и `status`, соответствие `layer` и `type`), `system-definitions.json` (`oneOf` по четырём видам определений: `type-definition`, `property-definition`, `relation-definition`, `field-expansion-rule`), `media.json` (обёртка `image` с обязательным `attachment` и значения `media` / `list<media>`). `additionalProperties` не запрещён: состав полей экземпляра вычисляется, а не хранится в схеме. Наборы `enum_values` конкретных свойств ядра в схемы не перенесены — источник нормы `07-core-properties.md`.

**Правила** (DL-038, DL-039): объект правила — восемь обязательных свойств плюс шесть служебных ключей (`rule_key`, `checks`, `severity`, `applies_to`, `condition`, `message`), `label` = `title`, `aliases[1]` = `rule_key`, `defined_by` — встроенный метатип 5, `id` выдаётся при создании. Первая волна — восемь правил, все `severity: error`: `unique-id` (INV-02), `filename-matches-object` (INV-05, INV-06), `aliases-first-equals-title` (INV-08), `media-target-is-image` (INV-23), `image-has-attachment` (INV-24), `extends-acyclic` (INV-18), `defined-by-consistent` (INV-12, INV-13), `trigger-values-subset` (INV-25). Предупреждения и остальные межобъектные проверки — кандидаты второй волны (реестр, раздел 7).

**Самопроверка итерации** (вне репозитория): синтаксис трёх схем проверен разбором JSON, поведение — мини-валидатором подмножества 2020-12 на 38 контрольных примерах (9 позитивных по каноническим примерам документации, 19 негативных, 10 проверок паттернов `canonical-link` и `media-link`); все проверки пройдены. Исполняемого валидатора, CI и кода плагина нет — они вне scope итерации.

Журнал решений — DL-001…DL-039, правила — R-001…R-007, реестр вопросов — Q-001…Q-011 (Q-001, Q-002 РЕШЕНО; Q-005, Q-006 ОТКЛОНЕНО в iter-009; Q-003, Q-004, Q-007…Q-011 ОТЛОЖЕНО). Далее — вторая волна фазы 2: регистрация служебных ключей `validation-rule` в реестре свойств, инвариант состава правила, схемы свойств ядра и значений фасетов, межобъектные правила (существование целей ссылок, уникальность машинных ключей, ацикличность `parent` / `part-of` / `blocks`), предупреждения (INV-27, глубина `extends`, Q-007).
