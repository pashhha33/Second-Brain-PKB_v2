## Состояние
Метамодель описана на уровне документов: реестры типов, свойств и отношений, механизм наследования, развёртывание полей и поведение интерфейса. Три слоя (`system`, `classification`, `content`), десять встроенных метатипов с фиксированными UUIDv7, реестр свойств с парой **key / label**, канонический набор из четырнадцати `value_type` (включая `media` и `list<media>`), четыре отношения классификации и четырнадцать отношений ядра, каноническая форма внутренней ссылки `[[{{type_prefix}}_{{id}}|{{title}}]]`, значения фасетов как объекты `facet-value`, процедура поведения при `status: deprecated`. Наследование типов — одиночное линейное: `extends` (`0..1`, каноническая ссылка), `excludes`, `field_order`, разрешение nearest wins, запрет циклов, детерминированный порядок представления полей. Ядро типов — 29 определений в пяти группах (Знания, Контекст, Медиа, Коллекции, Действия); свойства ядра — 23 определения с фиксированными `id`, из них три — свойства-триггеры (`occupation`, `format`, `creation-method`). Состав полей экземпляра вычисляется: базовый набор типа объединяется с полями активных правил развёртывания (`type: field-expansion`, `mode: union`); значения развёрнутых полей при деактивации правила не удаляются, а становятся неактивными (INV-25…INV-27). Инварианты — INV-01…INV-27 в двух файлах: `01-invariants.md` (универсальные INV-01…INV-12) и `09-structural-invariants.md` (структурные INV-13…INV-27). Поведение будущего плагина зафиксировано тремя контрактами (`10-plugin-ux-contracts.md`, ADR-008): видимость слоёв — три тумблера и три пресета, по умолчанию `content` и `classification` видимы, `system` скрыт, фильтрация действует в поиске и графе, проводник и quick switcher показывают всё; отображаемое имя — `title` вместо имени файла, подмена встроена в плагин (без зависимости от Front Matter Title), файл не переименовывается; создание из пустых ссылок — по явной команде, тип определяется контекстом свойства или отношения (`target_type`), создаваемый объект получает `status: draft` и каноническую ссылку, а свойства `media` и `list<media>` в создании из пустой ссылки не участвуют — обёртка `image` создаётся выбором файла (DL-034). Журнал решений — DL-001…DL-035, правила — R-001…R-007, реестр вопросов восстановлен (Q-001…Q-011). Далее — фаза 2: перенос инвариантов и реестров в JSON Schema и правила валидации.

## Открытые хвосты
- **UX-контракты не реализованы**: `10-plugin-ux-contracts.md` фиксирует поведение для фаз 4–5, кода нет (`plugin/` пуст), в том числе исключение `media` / `list<media>` из создания из пустой ссылки (DL-034). Соответствие контракту проверяется при приёмке фазы 5; отклонение — только через ADR.
- **Фильтрация слоёв не действует в проводнике и quick switcher** (решение человека, iter-007; ADR-008, А1; подтверждено в iter-008): перечень поверхностей в TASK.md iter-007 включал explorer и switcher, контракт описывает их поведение явно как «не фильтруются».
- **Подмена отображаемого имени действует только внутри плагина**: в веб-экспорте, сторонних приложениях и «голом» Markdown видно имя файла с UUID; компенсация — `title` в `aliases[0]` (INV-08) и в alias канонической ссылки (INV-15).
- **Пресеты видимости живут в настройках плагина, а не в модели**: при переустановке плагина пользовательские пресеты теряются, канонические три доступны всегда. Объектами модели пресеты не являются (DL-031).
- **`status: draft` у объектов, созданных из пустых ссылок**, требует от владельца явного перевода в `accepted` (INV-10, DL-011); массовой команды перевода статуса в контракте нет.
- **Статусы Q-004…Q-011 в реестре вопросов предложены агентом** (iter-008): решений Оркестратора по вопросам REPORT.md iter-005…iter-007 в коммитах A не было, подтверждение или пересмотр — в коммите A iter-009.
- **Указатели диапазонов DL пересмотрены не во всех файлах метамодели**: R-007 применён к файлам, затронутым DL-034 и DL-035 (`10`, `01`, `02`, `00`). В `03-builtin-types.md` (DL-009…DL-030), `04-properties.md` (…DL-029), `05-core-types.md` (…DL-028), `06-relations.md` (…DL-033), `07-core-properties.md` (…DL-028) и `09-structural-invariants.md` (DL-013…DL-030) перечислены записи, значимые для конкретного файла; вопрос о сплошной ревизии этих указателей — в REPORT.md iter-008.
- **`08-field-expansion.md` — 259 строк**: у границы R-006 (~300), Q-004. Расширение механизма (новые режимы `mode`, новые триггеры, примеры) требует остановки и вопроса о разбиении. `05-core-types.md` — 235 строк, `04-properties.md` — 213 строк, `02-layers.md` — 220 строк, `01-invariants.md` — 205 строк, `10-plugin-ux-contracts.md` — 179 строк, `OPEN_QUESTIONS.md` — 116 строк.
- **Триггеров три, и это ограничение первой версии** (TASK iter-006): `occupation`, `format`, `creation-method`. Новые триггеры — вопрос следующих итераций; стартовые `enum_values` не подтверждены (Q-005).
- **Режимы `mode` кроме `union` не определены** (ADR-006, S3, А5; DL-028): `first-match` и `override` отклонены и не нормативны; введение нового режима — через ADR.
- **Активность поля не хранится явно**: неактивное значение остаётся в данных и определяется только вычислением эффективного набора полей (INV-27). Маркер или история изменений не вводились.
- Машиночитаемые артефакты отсутствуют: JSON Schema и правила валидации — фаза 2 (`schema/`, `docs/validation/`). Реестры подготовлены к переносу: `property_key` → имя поля, `value_type` → тип (14 значений), `enum_values` → перечисление, `required` / `applies_to` / `cardinality` → ограничения, `extends` / `excludes` / `field_order` → базовый набор полей, `applies_to_type` / `trigger_property` / `trigger_values` / `adds_properties` / `adds_relations` / `mode` → эффективный набор полей, `layer` → фильтрация видимости, `target_type` → выбор типа при создании из пустой ссылки (кроме `media` / `list<media>`, DL-034). Критерий успеха фазы 2 — в `PROJECT_BRIEF.md`.
- **Существование файла по пути `attachment` инвариантом не проверяется** (INV-24); согласованность `trigger_values` с `enum_values` триггера на уровне данных (INV-25) тоже: оба — кандидаты в правила валидации фазы 2.
- **Роли `book` не хранятся полем** (DL-024): роль выводится из состава данных, а формат книги — свойство-триггер `format`; два механизма вывода должны согласовываться интерфейсом (Q-007).
- **Свойства пользовательских типов не фиксируются реестром**: реестр свойств ядра покрывает стартовый набор; правила развёртывания для пользовательских типов допустимы (INV-25), примеров в документации нет.
- **Переопределение параметров унаследованного поля на уровне типа не введено** (ADR-004, I3; Q-003): `value_type`, `required`, `cardinality` едины для всех типов. Кейс iter-006 — обязательность развёрнутого поля (`prompt`, `seed` при `creation-method: ai-generated`); правило развёртывания параметры полей не переопределяет (`08-field-expansion.md`, раздел 2, правило 5).
- Ядровые типы и правила развёртывания не имеют фиксированных `id` (DL-019); bootstrap ядра (29 типов, 14 отношений, 23 свойства) — опция плагина (фазы 4–5).
- Отношение «объект → домен» не вводится: домен выводится из `category-domain` его категорий (`06-relations.md`, раздел 2, правило 3).
- Примерные `id` в YAML-примерах не являются реестровыми; правило зафиксировано разделом «Иллюстративные `id` в примерах» в `03-builtin-types.md`.
- **Замечания вне scope, не исправленные** (Q-009, Q-010): формулировка `rand_a` в разделе «Как сгенерированы `id»» (`03-builtin-types.md`); неэкранированный `|` в двух ячейках таблиц ADR-003; указатели на `01-invariants.md` для INV-15…INV-24 в принятых ADR-003, ADR-004, ADR-005 (после разбиения iter-006 эти инварианты в `09-structural-invariants.md`); счётчик «девять встроенных метатипов» в исторической записи DL-021.
- **`PROJECT_BRIEF.md` начинается с H1 без 1–2 предложений о назначении файла** (R-002): замечено при правке статусов фаз в iter-008, не исправлено — файл вне перечня правок оформления.
- **Сводка закрытия критерия успеха фазы 1 в `00-overview.md` (строка 51) доведена до iter-005**: части критерия, закрытые в iter-006 (развёртывание полей) и iter-007 (UX-контракты), в абзац не добавлялись — вне scope iter-008.
