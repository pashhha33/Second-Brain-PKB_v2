# Реестр встроенных метатипов (системный слой)

Фиксированные `id`, `type`, `type_prefix` и `title` восьми встроенных метатипов системного слоя — точек замыкания самоописания модели. Реестр нормативен: значения `id` выдаются один раз и не меняются (INV-03), новые записи добавляются только через DL и обновление этого файла.

Слои модели — [`02-layers.md`](02-layers.md); правило вычисления `type_prefix` — DL-009 и [`../adr/ADR-001-identity-and-typing.md`](../adr/ADR-001-identity-and-typing.md) (R3); решение о трёх слоях — [`../adr/ADR-002-three-layers.md`](../adr/ADR-002-three-layers.md).

Все восемь объектов: `type: type`, `layer: system`, `status: accepted`, `owner: human`, `aliases[0] = title` (INV-08). Русские названия приведены в описаниях ниже и нормативными не являются — в свойствах объекта используется `title` из таблицы.

## Как сгенерированы `id`

Значения сгенерированы один раз (iter-002, 2026-10-27) и зафиксированы; повторная генерация не выполняется. Параметры генерации — для проверяемости:

- формат — UUIDv7 (RFC 9562): версия `7`, вариант RFC (`8`/`9`/`a`/`b`), каноническая строчная форма;
- `unix_ts_ms` (первые 48 бит) = `1793102400000` (2026-10-27T12:00:00Z) + номер записи в реестре (0…7), то есть метки времени идут строго возрастающе в порядке таблицы;
- `rand_a` (12 бит) и `rand_b` (62 бит) = старшие биты `SHA-256("SecondBrainPKB/iter-002/<type>/a")` и `SHA-256("SecondBrainPKB/iter-002/<type>/b")` с установкой бит версии и варианта;
- результат проверен: все восемь значений — валидные UUIDv7, уникальны, лексикографически возрастают.

## Метатипы системного слоя

### 1. `type` — Type (тип)

Определяет объекты-определения типов: встроенные метатипы и пользовательские типы (`person`, `book`, …). Объект с `type: type` обязан иметь свойство `type_value` — строку в ASCII kebab-case, которую будут использовать экземпляры этого типа (INV-13); `type_value` уникален в пределах хранилища.

Особое положение: это единственный метатип, чьё `defined_by` указывает на самого себя (`01a17d3b-4a00-747f-b063-cd02895e0d4f`). Самоотсылка замыкает цепочку самоописания модели и заменяет внешний реестр «типов типов».

- `defined_by` определяемых объектов: `01a17d3b-4a00-747f-b063-cd02895e0d4f`.
- Слой определяемых сущностей: `system`.

### 2. `property` — Property (свойство)

Определяет объекты-определения свойств: имя свойства, тип значения, обязательность, правило заполнения. Детальный состав свойств определения — в реестре свойств и отношений (планируется, iter-003).

- `defined_by` определяемых объектов: `01a17d3b-4a01-73dd-8782-259a7e45663f`.
- Слой определяемых сущностей: `system`.

### 3. `relation` — Relation (отношение)

Определяет объекты-определения отношений: источник, цель, направленность, кратность. Отношения используются в том числе для связей «объект → домен / категория / значение фасета» и «категория → родительская категория».

- `defined_by` определяемых объектов: `01a17d3b-4a02-7576-a16a-764c758b99be`.
- Слой определяемых сущностей: `system`.

### 4. `automation` — Automation (автоматизация)

Определяет объекты-правила автоматических действий (триггер → действие). Примеры назначений: синхронизация `aliases[0]` с `title` (INV-08), проверка соответствия имени файла и свойств (INV-06), простановка `status`.

- `defined_by` определяемых объектов: `01a17d3b-4a03-7afb-a20c-42cc54509281`.
- Слой определяемых сущностей: `system`.

### 5. `validation-rule` — Validation rule (правило валидации)

Определяет объекты-правила проверки данных: условие, сообщение об ошибке, признак активности. Правила можно добавлять и отключать без изменения кода плагина; машиночитаемая реализация — фаза 2 (`schema/`, `docs/validation/`).

- `defined_by` определяемых объектов: `01a17d3b-4a04-7c70-99cd-5c01dddac8b4`.
- Слой определяемых сущностей: `system`.

## Метатипы слоя классификации

Три метатипа ниже сами являются объектами системного слоя (`layer: system`), а определяют сущности слоя классификации (`layer: classification`). Состав зафиксирован человеком (TASK.md iter-002) и DL-010.

### 6. `domain` — Domain (домен)

Определяет домены — крупные предметные области, верхний уровень группировки без иерархии. Служит границей для иерархических категорий и областью видимости фасетов.

- `defined_by` определяемых объектов: `01a17d3b-4a05-7b2a-a236-1d80c3f98974`.
- Слой определяемых сущностей: `classification`.

### 7. `hierarchical-category` — Hierarchical category (иерархическая категория)

Определяет узлы дерева категорий внутри домена; иерархия задаётся отношением «родитель — потомок». Канонический идентификатор — `hierarchical-category` (DL-012); термин `taxonomy` сохранён в глоссарии как устаревший и не рекомендуется к использованию.

- `type_prefix` = `hierarchical-cat`: значение `type` длиной 21 символ обрезается до 16 по правилу DL-009 (шаг 5) — единственный случай обрезки в реестре.
- `defined_by` определяемых объектов: `01a17d3b-4a06-7991-b54e-9352cde369c0`.
- Слой определяемых сущностей: `classification`.

### 8. `facet` — Facet (фасет)

Определяет фасеты — независимые измерения классификации, значения которых комбинируются без иерархии (`Формат`, `Статус проработки`, `Год`). Объект слоя наполнения может иметь значение нескольких фасетов одновременно.

- `defined_by` определяемых объектов: `01a17d3b-4a07-7494-b6d9-328c7108a3c0`.
- Слой определяемых сущностей: `classification`.

## Полный объект реестра (пример записи 7)

```yaml
id: 01a17d3b-4a06-7991-b54e-9352cde369c0
type: type
defined_by: 01a17d3b-4a00-747f-b063-cd02895e0d4f   # встроенный метатип `type`
type_value: hierarchical-category                    # INV-13
title: Hierarchical category
aliases:
  - Hierarchical category
layer: system
status: accepted
owner: human
# имя файла: hierarchical-cat_01a17d3b-4a06-7991-b54e-9352cde369c0.md
```

## Правила работы с реестром

1. **`id` неизменяемы** (INV-03). Замена `id` метатипа равносильна замене модели и требует нового ADR.
2. **Метатипы не удаляются и не переводятся в `deprecated`**: это ломает самоописание модели и обесценивает `defined_by` существующих объектов.
3. **Значения `type` метатипов не переименовываются**: от них производны `type_prefix` и имена файлов (INV-05, INV-06).
4. **Новый встроенный метатип** добавляется только через DL: новая запись в конец таблицы, новый `id` по тому же правилу генерации, обновление `02-layers.md` и глоссария.
5. **Пользовательские типы не попадают в этот реестр**: они создаются в хранилище как объекты `type: type` со своим `id` (см. [`02-layers.md`](02-layers.md), системный слой).
6. **Bootstrap**: при инициализации хранилища создаются восемь заметок с указанными именами файлов и свойствами из этого реестра; реализация — фазы 4–5 (`plugin/`).
