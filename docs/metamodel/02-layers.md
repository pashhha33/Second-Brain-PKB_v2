# Слои модели: schema и instance

Метамодель двухслойна: слой **схемы** (`layer: schema`) содержит определения — типы, свойства, отношения, таксономии, фасеты, правила валидации; слой **экземпляров** (`layer: instance`) содержит объекты предметной области, созданные по этим определениям. Оба слоя состоят из одних и тех же объектов и подчиняются одним и тем же инвариантам ([`01-invariants.md`](01-invariants.md)).

## Почему два слоя, а не «код + данные»

Принцип самоопределения (`../PROJECT_BRIEF.md`) означает: определение типа — это заметка в том же хранилище, а не сущность в коде плагина. Поэтому различие между определением и экземпляром выражается **свойством объекта** (`layer`), а не местом хранения или форматом файла. Следствие: новый тип появляется как новая заметка, и плагин узнаёт о нём без изменения кода.

## Сравнение слоёв

| Признак | `schema` | `instance` |
|---|---|---|
| Что содержит | определения: тип, свойство, отношение, таксономия, фасет, правило валидации | объекты предметной области: человек, книга, идея, встреча |
| Значение `type` | один из встроенных метатипов (`type`, `property`, `relation`, …) | значение, определённое объектом слоя `schema` (`person`, `book`, …) |
| Кто создаёт | пользователь как автора модели | пользователь (или автоматизация) при добавлении знаний |
| Пример `title` | `Person` (имя типа) | `Иван Петров` (имя сущности) |
| Пример имени файла | `type_019a1b2c-7d3e-7f40-8a1b-2c3d4e5f6a70.md` | `person_019a1b2d-9e4f-7a50-8b21-3c4d5e6f7a81.md` |
| Что означает `status: accepted` | определение стабильно, экземпляры могут на него опираться | объект завершён и используется в ссылках |
| Изменение после `accepted` | с ограничениями: правка определения затрагивает все экземпляры | свободное, кроме `id` (INV-03) и нежелательной смены `type` (INV-04) |
| Обязательное дополнительное свойство | объявление того, что объект описывает (INV-12) | нет |

Оба слоя используют одинаковый минимальный набор свойств: `id`, `type`, `title`, `aliases`, `layer`, `status`, `owner`.

## Самоописание схемы

Слой схемы описывает сам себя теми же средствами, что и экземпляры:

- объект, определяющий тип `person`, сам имеет `id` (UUIDv7), `type`, `title`, `layer: schema`, `status`, `owner` и имя файла по правилу `{{type_prefix}}_{{id}}`;
- значение его `type` — встроенный метатип (например, `type`), то есть «тип» — это объект, тип которого определён в той же модели;
- цепочка самоописания конечна: она замыкается на **встроенных метатипах** — объектах слоя `schema`, которые присутствуют в хранилище изначально и не определяются через другие объекты. Их `id` и `type_prefix` будут зафиксированы реестром встроенных метатипов (следующая итерация фазы 1, планируемый файл `03-builtin-types.md`).

Пример пары «определение → экземпляр» (значения `id` иллюстративные):

```yaml
# слой схемы — определение типа
id: 019a1b2c-7d3e-7f40-8a1b-2c3d4e5f6a70
type: type
title: Person
aliases:
  - Person
layer: schema
status: accepted
owner: human
# имя файла: type_019a1b2c-7d3e-7f40-8a1b-2c3d4e5f6a70.md
# значение типа, которое будут использовать экземпляры: person
```

```yaml
# слой экземпляров — объект предметной области
id: 019a1b2d-9e4f-7a50-8b21-3c4d5e6f7a81
type: person
title: Иван Петров
aliases:
  - Иван Петров
layer: instance
status: accepted
owner: human
# имя файла: person_019a1b2d-9e4f-7a50-8b21-3c4d5e6f7a81.md
```

Связь экземпляра с определением — через значение `type`. Формальное свойство-указатель и правило его проверки уточняются вместе с реестром встроенных метатипов (INV-12).

## Как `type` и имя файла работают на обоих слоях

1. **Значение `type` всегда строка в ASCII kebab-case** (INV-04) — и у определения (`type: type`, `type: property`), и у экземпляра (`type: person`).
2. **`type_prefix` вычисляется из `type` одинаково на обоих слоях** (INV-05, DL-009): никакого отдельного правила для схемы нет.
3. **Имя файла формируется одинаково** (INV-06): `{{type_prefix}}_{{id}}`. Различие слоёв видно в имени файла только через префикс, унаследованный от `type` (`type_…`, `property_…` против `person_…`, `book_…`).
4. **Уникальность имён файлов обеспечивается единым пространством `id`** (INV-02): схема и экземпляры не имеют отдельных пространств идентификаторов, поэтому коллизия имён между слоями невозможна.
5. **Слой не кодируется в имени файла**: папка и префикс не заменяют свойство `layer`; при переносе файла между папками слой и идентичность сохраняются.

## Переходы между слоями

- Объект не «переходит» из слоя в слой: значение `layer` задаётся при создании и отражает роль объекта. Изменение роли равносильно созданию нового объекта (новый `id`).
- Определение типа проходит путь `draft` → `accepted`: пока тип в `draft`, экземпляры этого типа считаются черновыми и не используются как основа автоматизаций.
- Удаление определения из слоя `schema` не допускается без обработки его экземпляров; процедура снятия типа с эксплуатации (статус, отличный от `accepted`, и миграция экземпляров) будет определена в следующей итерации фазы 1.
