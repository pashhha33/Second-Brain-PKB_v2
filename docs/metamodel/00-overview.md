# Метамодель — обзор (фаза 1)

Обзор метамодели Second Brain PKB: что она описывает, какие артефакты входят в фазу 1, в каком порядке они появляются и что сознательно отложено на следующие фазы. Документ — точка входа в `docs/metamodel/`.

## Что такое метамодель

Метамодель — описание того, как устроены объекты базы знаний: что обязательно есть у каждого объекта, как объект называется, как он относится к своему типу и чем экземпляры отличаются от определений. Ключевой принцип проекта (см. [`../PROJECT_BRIEF.md`](../PROJECT_BRIEF.md)) — **самоопределение**: тип, свойство, отношение и правило валидации являются объектами той же модели и подчиняются тем же инвариантам.

Метамодель не задаёт перечень типов предметной области (Person, Book, Note…). Она задаёт правила, по которым такие типы могут быть добавлены без изменения кода плагина.

## Границы фазы 1

**Входит в фазу 1:**

- жёсткие инварианты объекта (идентичность, имя файла, тип, заголовок, слой, статус, владелец);
- разделение модели на слой схемы и слой экземпляров, правило самоописания;
- первичный глоссарий терминов;
- ADR по фундаментальным решениям (идентичность и типизация);
- журнал решений DL-006…DL-009.

**Не входит в фазу 1 (осознанно отложено):**

- конкретные типы предметной области и их наборы свойств;
- реестр встроенных метатипов (type, property, relation, taxonomy, facet, automation, validation-rule) с фиксированными `id`;
- JSON Schema и машиночитаемые правила валидации — фаза 2 (`schema/`, `docs/validation/`);
- примеры и шаблоны заметок — фаза 3 (`examples/`);
- любая реализация в плагине — фазы 4–5 (`plugin/`).

Критерий успеха фазы 1 (из `PROJECT_BRIEF.md`): метамодель описана так, что по ней можно реализовать плагин без дополнительных устных договорённостей. Полностью этот критерий закрывается фазами 1–2; после iter-001 закрыта часть «как устроен объект, как формируется имя заметки, какие свойства обязательны».

## Порядок появления артефактов

1. **Инварианты** — сначала фиксируется минимум, без которого объект не существует (iter-001).
2. **Слои** — на инвариантах объясняется, чем определение типа отличается от экземпляра (iter-001).
3. **ADR-001** — фиксирует выбор формата `id`, правила имени файла и производности `type_prefix` вместе с альтернативами (iter-001).
4. **Глоссарий** — наполняется по мере появления артефактов; после iter-001 содержит базовый набор терминов (iter-001).
5. **Реестр встроенных метатипов** — следующий шаг: конкретные объекты слоя схемы с фиксированными `id` (планируется).
6. **Реестр свойств и отношений** — базовый набор свойств и отношений модели (планируется).
7. **Машиночитаемая схема** — фаза 2, перенос инвариантов в JSON Schema и правила валидации.
