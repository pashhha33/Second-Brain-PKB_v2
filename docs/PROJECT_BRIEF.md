# PROJECT BRIEF — Second Brain PKB

## Видение

Личная база знаний, в которой структура не задана заранее жёстко, а описывается той же базой. Пользователь добавляет новый тип объекта, свойство или отношение — и система узнаёт о нём без изменения кода.

## Ключевые принципы

1. **Самоопределение.** Тип — это объект. Свойство — объект. Отношение — объект. Всё имеет `id` и `type`.
2. **Расширяемость без правки плагина.** Новый тип = новая заметка, а не новая версия кода.
3. **Явная семантика.** У каждого объекта есть слой (схема / экземпляр), статус (черновик / принято) и владелец.
4. **Проверяемость.** Правила валидации — тоже объекты; их можно добавлять и отключать.

## Что входит в проект

| Часть | Назначение |
|---|---|
| Метамодель | описание того, как устроены объекты, свойства, отношения, таксономии, фасеты, автоматизации |
| Документация | глоссарий, реестр типов, правила, примеры |
| ADR | зафиксированные архитектурные решения с альтернативами |
| JSON Schema | машиночитаемые артефакты для проверки |
| Плагин Obsidian | реализация метамодели: TypeScript + Obsidian API |
| Примеры | эталонные экземпляры и шаблоны заметок |

## Ограничения

- Плагин: TypeScript, Obsidian API, работа офлайн, без внешних зависимостей без ADR.
- Документация: русский. Код и схемы: английский.
- Один человек пишет в репозиторий; ИИ работают в режиме «чтение / песочница».

## Критерий успеха фазы 1

Метамодель описана так, что по ней **можно** реализовать плагин без дополнительных устных договорённостей: каждый тип, свойство и отношение имеют определение, пример и контракт поведения — в данных и в интерфейсе. Машиночитаемое правило валидации в критерий фазы 1 не входит: оно появляется в фазе 2 (DL-035, уточнение критерия — iter-008).

## Критерий успеха фазы 2

Каждый инвариант (INV-01…INV-27) и каждое реестровое ограничение имеют машиночитаемое выражение: JSON Schema в `schema/` или правило валидации как объект `type: validation-rule` в `docs/validation/`; правило можно добавить и отключить без изменения кода плагина (принцип 4).

Статус на iter-009: критерий выполнен для ядра объекта (INV-01…INV-12), определений системного слоя `type`, `property`, `relation`, `field-expansion` (INV-13, INV-15…INV-22, INV-25) и обёртки `image` со значениями `media` / `list<media>` (INV-23, INV-24). Остальное — следующие итерации фазы 2: значения фасетов, определения `automation` и `validation-rule`, свойства ядра и специфичные формы их значений, экземпляры типов слоя наполнения (ADR-009, S4 и S6), а также межобъектные проверки второй волны — существование целей ссылок, уникальность машинных ключей, ацикличность `parent` / `part-of` / `blocks`, предупреждения по INV-27 и Q-007 (`docs/validation/00-validation-rules.md`, раздел 7). Вычисления (эффективный набор полей INV-20, INV-26) проверяются алгоритмом плагина в фазах 4–5, а не схемой.
