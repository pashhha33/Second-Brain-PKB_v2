# Правила валидации: вторая волна

Описания шести правил второй волны (iter-010): три межобъектные проверки с `severity: error` и три предупреждения. Формат объекта и состав ключей — [`00-validation-rules.md`](00-validation-rules.md), раздел 3; граница «схема — правило» — [`../adr/ADR-009-phase2-schemas.md`](../adr/ADR-009-phase2-schemas.md) (S1); состав волны и шкала тяжести — DL-040, схема объекта правила — DL-041. Правила первой волны — [`01-first-wave-rules.md`](01-first-wave-rules.md).

`id` правил иллюстративные: у правил валидации фиксированных `id` нет, они выдаются при создании объекта (DL-038, по образцу DL-019 и DL-029). Все правила волны — `status: accepted`, `layer: system`, `owner: human`.

Значения ключа `checks` — идентификаторы нормативных ограничений трёх видов (DL-040): `INV-NN` (инвариант), `DL-NNN` (решение журнала) и `<имя файла реестра>#<раздел>.<пункт>` — для ограничений, у которых нет инварианта (ацикличность отношений, уникальность `rule_key`). Если у ограничения есть инвариант, он указывается обязательно.

## 1. `link-target-exists` — цель канонической ссылки существует

```yaml
id: 01a17d3b-9b09-748a-8bf0-17d91ce8f0d9
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: link-target-exists
title: Цель канонической ссылки существует
aliases: [Цель канонической ссылки существует, link-target-exists]
checks: [INV-15, INV-23]
severity: error
applies_to: "*"
condition: "Каждая каноническая внутренняя ссылка в значениях frontmatter — у свойств с value_type link, list<link>, media, list<media> и у отношений — разрешается в существующий объект хранилища: файл с именем {{type_prefix}}_{{id}}.md присутствует, а id цели совпадает со свойством id этого объекта."
message: "Ссылка не разрешается: объект с таким id отсутствует в хранилище либо имя файла цели не соответствует её типу и идентификатору."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** определить ключи frontmatter, значения которых являются ссылками, по реестрам ([`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 5; [`../metamodel/07-core-properties.md`](../metamodel/07-core-properties.md); [`../metamodel/06-relations.md`](../metamodel/06-relations.md), разделы 1–3); извлечь из канонической формы `id` цели и `type_prefix`, найти объект по имени файла, сверить `id`; для значений-списков проверить каждый элемент.
- **Границы:** форма ссылки (префикс цели, наличие alias) контролируется схемой ([`../../schema/object.json`](../../schema/object.json) — `$defs/canonical-link`, [`../../schema/media.json`](../../schema/media.json) — `$defs/media-link`); ссылки в теле заметки правилом не проверяются — пустая ссылка в теле допустима и обрабатывается контрактом создания объекта из пустой ссылки (DL-033, [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), раздел 4); `defined_by` — исключение из INV-15 и проверяется правилом первой волны `defined-by-consistent`; `attachment` ссылкой не является (INV-24), существование файла вложения — кандидат третьей волны; равенство alias ссылки и `title` цели (INV-15) — кандидат третьей волны (`severity: warning`, нормализуется плагином); цель в `status: deprecated` существует, поэтому правило не срабатывает — предупреждение выдаёт `deprecated-link-target`.

## 2. `unique-machine-keys` — машинные ключи уникальны

```yaml
id: 01a17d3b-9b0a-759b-9c01-28ea2df90a1a
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: unique-machine-keys
title: Машинные ключи уникальны
aliases: [Машинные ключи уникальны, unique-machine-keys]
checks: [INV-13, INV-16, INV-17, DL-038]
severity: error
applies_to: [type, property, relation, validation-rule]
condition: "Во всём хранилище не более одного объекта с данным значением машинного ключа: type_value у определений типов, property_key у определений свойств, relation_key у определений отношений, rule_key у правил валидации."
message: "Найден второй объект с тем же машинным ключом: ключ служит именем поля в frontmatter и идентификатором определения, дубль делает данные неоднозначными."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** собрать пары «(вид ключа, значение) → объекты» для объектов системного слоя четырёх типов; сравнение точное, регистр значим (ключи — строки в нижнем регистре по INV-04, INV-16, INV-17); группа больше одного объекта — ошибка на всех объектах группы с указанием вида ключа и значения.
- **Границы:** объекты в `status: deprecated` участвуют в проверке — `type_value` не переиспользуется даже после вывода определения из эксплуатации ([`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 7.2); форма ключа контролируется схемой ([`../../schema/object.json`](../../schema/object.json) — `$defs/field-key`); неизменяемость ключа после перехода в `accepted` (INV-13, INV-16, INV-17) — ограничение редактирования, контроль выполняет плагин (фазы 4–5); равенство `aliases[1]` машинному ключу (INV-16, INV-22) и коллизия `type_prefix` у двух разных `type_value` (ADR-001, DL-009) — кандидаты третьей волны.

## 3. `relation-acyclic` — иерархические отношения ацикличны

```yaml
id: 01a17d3b-9b0b-76ac-8d12-39fb3e0a1b2b
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: relation-acyclic
title: Иерархические отношения ацикличны
aliases: [Иерархические отношения ацикличны, relation-acyclic]
checks: ["06-relations.md#2.1", "06-relations.md#3.2"]
severity: error
applies_to: "*"
condition: "Обход по значениям отношений parent (объекты hierarchical-category), part-of (любые объекты) и blocks (объекты task, goal, decision, project) не возвращается к уже посещённому объекту: объект не может быть собственным родителем, собственным целым или блокирующим сам себя по цепочке."
message: "Цикл в значении отношения: объект участвует в собственной цепочке, обход графа невычислим."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** по каждому из трёх `relation_key` отдельно построить ориентированный граф «источник → цели» (значение-список даёт несколько рёбер, одиночная ссылка — одно), обойти от каждой вершины с множеством посещённых; повторное посещение — ошибка на объектах цикла. Графы разных ключей не смешиваются: цепочка из рёбер `part-of` и `blocks` одновременно циклом не считается.
- **Границы:** основание — [`../metamodel/06-relations.md`](../metamodel/06-relations.md), раздел 2, правило 1 (`parent`: «Циклы запрещены») и раздел 3, правило 2 (`part-of` и `blocks` обязаны быть ацикличными); инварианта с номером у ограничения нет, поэтому `checks` ссылается на пункты реестра (DL-040). `contradicts` симметрично (раздел 3, правило 2) и на ацикличность не проверяется; `chapter-of` (`chapter` → `book`, `1..1`) и `part-of-collection` (элемент → коллекция, `0..*`) типизированы так, что цикл требует нарушения `source_type` / `target_type` определения, — соответствие типа объекта области отношения является кандидатом третьей волны; неразрешимая ссылка в значении отношения — ошибка правила `link-target-exists`, а не цикл; согласованность `category-domain` в одной ветке категорий (раздел 2, правило 2) и форма значения при кратности `0..1` (список вместо одиночной ссылки) — кандидаты третьей волны.

## 4. `inactive-field-value` — неактивное поле со значением

```yaml
id: 01a17d3b-9b0c-77bd-9e23-4a0c4f1b2c3c
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: inactive-field-value
title: Неактивное поле со значением
aliases: [Неактивное поле со значением, inactive-field-value]
checks: [INV-27, DL-028]
severity: warning
applies_to: "*"
condition: "В frontmatter объекта присутствует непустое значение поля, добавленного правилом развёртывания, которое перестало быть активным для этого объекта: значение свойства-триггера изменено или удалено либо правило переведено в draft или deprecated."
message: "Поле неактивно, но содержит значение: данные сохранены, поле скрыто из формы; очистка выполняется только явной командой владельца."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** вычислить эффективный набор полей объекта (INV-20, INV-26: объявления типов цепочки `extends` за вычетом `excludes` плюс поля активных правил развёртывания); для каждого ключа frontmatter вне этого набора проверить, объявлен ли он в `adds_properties` или `adds_relations` какого-либо правила развёртывания; если объявлен, правило для объекта неактивно, а значение непустое — предупреждение.
- **Границы:** «осиротевшее значение» — предупреждение, а не ошибка и не нарушение инварианта (INV-27); автоматическое удаление значений запрещено, очистка неактивных полей — явная команда владельца (DL-028, [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 7); возврат значения триггера снова делает правило активным, и предупреждение снимается без повторного ввода данных (INV-27); ключи, не объявленные ни в одном правиле развёртывания, предупреждения не вызывают — соответствие значения области применения определения свойства (`applies_to`) является кандидатом третьей волны; обязательные свойства (INV-01…INV-12) и служебные ключи определений системного слоя в проверке не участвуют.

## 5. `extends-depth` — глубина цепочки наследования

```yaml
id: 01a17d3b-9b0d-78ce-8f34-5b1d502c3d4d
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: extends-depth
title: Глубина цепочки наследования
aliases: [Глубина цепочки наследования, extends-depth]
checks: [INV-18]
severity: warning
applies_to: [type]
condition: "Число предков определения типа по цепочке extends больше пяти."
message: "Цепочка extends глубже пяти уровней: эффективный набор полей типа трудно прочитать, рекомендуется сократить цепочку или перенести поля в определение типа."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** от определения по `extends` до корня цепочки, считая переходы; больше пяти — предупреждение на определении-листе, на промежуточных уровнях не дублируется.
- **Границы:** глубина до пяти уровней — рекомендация, а не ограничение: «превышение является предупреждением, а не ошибкой» (INV-18; [`../adr/ADR-004-type-inheritance.md`](../adr/ADR-004-type-inheritance.md), I1); цикл в цепочке — ошибка правила первой волны `extends-acyclic`; требование «родитель — не встроенный метатип» (INV-18, INV-14) — кандидат третьей волны; ядро типов цепочек глубже двух уровней не имеет ([`../metamodel/05-core-types.md`](../metamodel/05-core-types.md), сводка), поэтому в стартовом хранилище правило не срабатывает и предназначено для пользовательских типов.

## 6. `deprecated-link-target` — ссылка на устаревший объект

```yaml
id: 01a17d3b-9b0e-79df-9045-6c2e613d4e5e
type: validation-rule
defined_by: 01a17d3b-4a04-7c70-99cd-5c01dddac8b4
rule_key: deprecated-link-target
title: Ссылка на устаревший объект
aliases: [Ссылка на устаревший объект, deprecated-link-target]
checks: [INV-10, "04-properties.md#7.1"]
severity: warning
applies_to: "*"
condition: "Объект в status: accepted или draft имеет в значении свойства (link, list<link>, media, list<media>) или отношения каноническую ссылку на объект в status: deprecated; значение defined_by не проверяется."
message: "Цель ссылки в статусе deprecated: ссылка действительна, новые привязки по ней не создаются; при необходимости выполните миграцию на заменитель явной командой."
layer: system
status: accepted
owner: human
```

- **Алгоритм:** для каждой канонической ссылки в значениях frontmatter, кроме `defined_by`, загрузить объект-цель и проверить его `status`; значение `deprecated` — предупреждение на объекте-источнике с указанием ключа и цели.
- **Границы:** ссылка на объект в `deprecated` действительна и ошибкой не считается ([`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 7.1, пункты 1–2), поэтому `severity: warning`; `defined_by` исключён из проверки — `defined_by` существующих экземпляров продолжает указывать на определение типа в `deprecated` (раздел 7.2); предупреждение информирует о миграции и не требует удаления значения: автоматический перенос значений запрещён, он выполняется явной автоматизацией или вручную (раздел 7.5); контракт «плагин не предлагает новые привязки к объекту в `deprecated`» (разделы 7.3 и 7.5) проверкой не заменяется; перевод объекта в `deprecated` не проверяет входящие ссылки массово — предупреждения появляются на источниках постепенно, по мере их чтения и сохранения; возврат цели в `accepted` допустим и снимает предупреждение (раздел 7.1, пункт 3); объект-источник в `status: deprecated` не проверяется — его состав ссылок не развивается.
