# OPEN QUESTIONS — реестр вопросов

Собирает все вопросы со статусами `ОТЛОЖЕНО`, `ОТКЛОНЕНО`, `К ЧЕЛОВЕКУ`, плюс историю закрытий (`РЕШЕНО`).

## Формат записи

```
Q-NNN (iter-NNN, YYYY-MM-DD): вопрос
  Статус: РЕШЕНО РЕШЕНИЕМ / РЕШЕНО ПРАВИЛОМ / ОТЛОЖЕНО / ОТКЛОНЕНО / К ЧЕЛОВЕКУ
  Ответ: формулировка
  Ссылка: DL-XXX / R-XXX / ADR-XXX / Q-XXX
  Триггер: условие пересмотра (только для ОТЛОЖЕНО)
```

Пять статусов — по [`HANDOFF_PROTOCOL.md`](HANDOFF_PROTOCOL.md), раздел о статусах вопросов. Реестр ведёт Оркестратор (коммит A); восстановление файла в iter-008 выполнено агентом по прямому указанию [`iterations/iter-008/TASK.md`](iterations/iter-008/TASK.md), п. 3 (см. раздел «Примечания о ведении реестра»).

## Примечания о ведении реестра

1. Записи Q-004…Q-011 внесены агентом в iter-008 при восстановлении реестра (TASK.md iter-008, п. 3). Статус `ОТЛОЖЕНО` и формулировки триггеров предложены агентом: решений Оркестратора по этим вопросам в коммитах A iter-006…iter-008 не было. Требуется подтверждение или пересмотр статусов в коммите A iter-009.
2. Формулировки Q-001 и Q-002 восстановлены по полной версии файла из коммита `be13303` (коммит A iter-004): в коммитах A iter-005…iter-007 записи сокращались, а в iter-007 файл сведён к трём строкам без формулировок, ответов и триггеров. Полная формулировка Q-003 в репозитории не сохранялась — восстановлена по REPORT.md iter-004, вопрос 3 и REPORT.md iter-006, вопрос 5.
3. Вопросы REPORT.md iter-002…iter-005, снятые указаниями последующих TASK.md (язык `label` встроенных метатипов, `excludes` по `relation_key`, имя ключа `field_order`, абстрактные типы, фиксированные `id` отношений ядра, иллюстративные `id` в YAML-примерах, разбиение `04-properties-relations.md` и `01-invariants.md`), отдельными записями не регистрировались: решения зафиксированы в DL, ADR и в тексте TASK соответствующих итераций.
4. Q-005 и Q-006 закрыты статусом `ОТКЛОНЕНО` агентом в iter-009 по прямому указанию TASK.md iter-009, п. 3 («вопросы-подтверждения без возражений»); отклонение от правила «реестр ведёт Оркестратор» зафиксировано в REPORT.md iter-009. Подтверждения статусов Q-003, Q-004 и Q-007…Q-011 в коммите A iter-009 не получено — они остаются `ОТЛОЖЕНО`.
5. Реестр ведёт Оркестратор (коммит A) — [`HANDOFF_PROTOCOL.md`](HANDOFF_PROTOCOL.md), таблица «Служебные файлы — кто пишет». Правка файла агентом в iter-008 — исключение по прямому указанию TASK.md; отклонение зафиксировано в REPORT.md iter-008. С iter-010 такое исключение закреплено протоколом: агент может технически обновлять реестр по явному указанию пункта TASK.md, присвоенные им статусы считаются предварительными до приёмки Оркестратором, а перечень правок приводится в REPORT.md (DL-042). Записи Q-001…Q-011 в iter-010 не пересматривались: указание TASK.md iter-010 касалось только уточнения указателей.
