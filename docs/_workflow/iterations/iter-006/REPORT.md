2. **Цель 1 — S1: правило как объект системного слоя.** Объект `type: field-expansion` (встроенный метатип 10) со служебными ключами `applies_to_type` (`list<string>`, непустой), `trigger_property` (`string`), `trigger_values` (`list<string>`, непустое подмножество `enum_values` триггера), `adds_properties` / `adds_relations` (хотя бы один непустой), `mode` (`enum`, в v1 единственное значение `union`). `id` правила не фиксируется реестром и выдаётся при создании (по образцу типов ядра, DL-019); ссылки в правиле — на `key`, а не на `id`.
3. **Цель 1 — S2: понятие триггера.** Свойство-триггер — свойство с `value_type: enum` (одиночный выбор) или `list<enum>` (мультивыбор) и непустым `enum_values`; триггером может быть и свойство пользовательского типа, не только ядра; `enum_values` определения ядра — стартовый набор, расширяемый владельцем без смены `value_type` (новое правило 4 раздела 2 [`04-properties.md`](../../../metamodel/04-properties.md)).
4. **Цель 1 — S3: семантика мультивыбора (`mode: union`).** Значение `list<enum>` может активировать несколько правил; результат — объединение `adds_properties` и `adds_relations` всех активных правил; объединение идемпотентно и коммутативно, порядок представления детерминирован (поля типа по INV-20, затем добавленные — по возрастанию `id` правил, внутри правила — по порядку перечисления). Режимы `first-match` и `override` отклонены (А5): они требуют приоритетов и порядка правил, чего в v1 нет (DL-028).
5. **Цель 1 — S4: эффективный набор полей экземпляра.** Алгоритм из шести шагов (раздел 4 [`08-field-expansion.md`](../../../metamodel/08-field-expansion.md)): эффективный набор типа → отбор правил (`type: field-expansion`, `status: accepted`, `layer: system`) → проверка `applies_to_type` с учётом цепочки `extends` → проверка значения триггера → объединение → упорядочивание. Нормативно закреплён INV-26.
6. **Цель 1 — S5: смена и удаление значения триггера.** Данные не удаляются: поле, добавленное правилом, которое перестало быть активным, переходит в состояние **неактивного** — интерфейс скрывает его из формы, значение во frontmatter сохраняется; неактивное поле с непустым значением — предупреждение правила валидации фазы 2 («осиротевшее значение»), а не ошибка; автоматическое удаление запрещено, очистка — явная команда владельца с подтверждением. Обоснование: заметка — источник истины, потеря введённых данных недопустима, а стоимость хранения неактивного ключа ниже стоимости восстановления (ADR-006, S5; А4 — отклонены варианты «удалять значения» и «блокировать смену триггера»; INV-27; DL-028).

## Отклонения от TASK.md

1. **`creation_method` → `creation-method`.** В TASK.md имя триггера приведено в snake_case; по R-001 и DL-014 `property_key` — английский ASCII kebab-case (INV-04 запрещает подчёркивания в `type`, INV-16 — в `property_key`). Зафиксировано `creation-method`.
