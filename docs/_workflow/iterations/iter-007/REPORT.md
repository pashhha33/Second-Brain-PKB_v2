## Что сделано

1. **Цель 1, блок «видимость слоёв» — ADR-008 (U1) и раздел 2 контракта.** Три глобальных тумблера по значению `layer` (INV-09): `system`, `classification`, `content`; состояние — в настройках плагина, не в данных объектов. Три канонических пресета («Только знания» = `content`; «Модель» = `system` + `classification`; «Всё» = все три) таблицей; пользовательские пресеты — в настройках плагина, объектами модели не являются (новый метатип не вводился). Состояние по умолчанию: `content` и `classification` видимы, `system` скрыт, с обоснованием (служебные определения нужны при настройке модели, классификация участвует в повседневной навигации) и командой сброса. Таблица поверхностей: фильтрация — в поиске (исключение из выдачи и счётчика) и в графе (узлы и инцидентные рёбра, глобальный и локальный); проводник, quick switcher, панели ссылок и предпросмотр — не фильтруются, применяется только отображаемое имя. Зафиксировано, что видимость не влияет на данные, разрешение ссылок, нормализацию, наследование, вычисление эффективного набора полей и валидацию; файлы вне модели не относятся ни к слою и не скрываются.
2. **Цель 1, блок «display title» — ADR-008 (U2) и раздел 3 контракта.** Источник — `title` (INV-07), не имя файла и не отдельное свойство; поверхности подмены — проводник, заголовок вкладки, заголовок заметки, результаты поиска, quick switcher, подписи узлов графа, панели обратных и исходящих ссылок, всплывающий предпросмотр, поле значения свойства-ссылки в форме. В тексте заметки подмена не нужна: каноническая ссылка несёт alias = `title` (INV-15). Подмена встроена в наш плагин: Front Matter Title — референс поведения, зависимостью не является (основание — `PROJECT_BRIEF.md`: без внешних зависимостей без ADR; ADR-008 фиксирует отказ от зависимости). Файл не переименовывается (INV-05, INV-06; `id` неизменяем, INV-03), содержимое заметок подменой не изменяется. При изменении `title` обновляются alias во всех ссылках (`06-relations.md`, раздел 4, правило 3), `aliases[0]` (INV-08) и отображение. Совпадения `title` (ADR-001, R6) разрешаются индикатором: `label` определения типа, для определений системного слоя — `key` (DL-021); у встроенных метатипов `title` английский (INV-14), русское имя из `aliases[1]` — подсказка. Файлы вне модели отображаются как есть; отсутствие `title` у объекта модели — нарушение INV-07 с пометкой об ошибке.
3. **Цель 1, блок «empty-link creation» — ADR-008 (U3) и раздел 4 контракта.** Пустая ссылка — `[[…]]`, не разрешающаяся в существующий файл; создание **только по явной команде** (клик или контекстное меню), автоматически при сохранении — нет. Таблица выбора типа по четырём контекстам: в теле заметки — выбор из определений `type: type` со `status: accepted` (ядро и пользовательские, `deprecated` исключены); в значении свойства или отношения с единственным допустимым `target_type` — этот тип без запроса (`chapter-of` → `chapter`, `narrator` → `person`); с несколькими целями — выбор среди них (`part-of-collection` → `film-series`, `album`, `gallery`); при ключе вне реестров — как в теле. Допустимые цели берутся из определения отношения (`target_type`, INV-17) или свойства (`value_type`, `applies_to`; INV-16, INV-21) на момент команды.
4. **Состав создаваемого объекта** — таблица со ссылками на инварианты: `id` (новый UUIDv7, INV-01, INV-02), `type` (INV-04), имя файла `{{type_prefix}}_{{id}}.md` (INV-05, INV-06), `defined_by` (INV-12), `title` — alias ссылки, иначе текст цели, с сохранением регистра и пробелов (INV-07), `aliases[0] = title` (INV-08), `layer` — значение, требуемое INV-09 для выбранного типа (`content` для типов слоя наполнения, `classification` для `domain`, `hierarchical-category`, `facet`, `facet-value`), `status: draft` (INV-10, DL-011), `owner` — владелец хранилища (INV-11), остальные поля — значения по умолчанию определения и развёртывание полей (`08-field-expansion.md`, раздел 4). Объекты системного слоя из пустых ссылок не создаются (bootstrap или явная команда создания определения).
5. **Нормализация ссылки и дубликаты.** Ссылка в месте создания заменяется канонической формой `[[{{type_prefix}}_{{id}}|{{title}}]]` (INV-15, `06-relations.md`, раздел 4, правило 1), alias добавляется из `title` созданного объекта, значение записывается туда, где стояла ссылка (тело или ключ frontmatter по `property_key` / `relation_key`). Перед созданием выполняется поиск объектов с совпадающим `title` или элементом `aliases` (нормализованное сравнение) с предложением связать ссылку с существующим объектом; дубль — только после явного подтверждения. Отмена не изменяет заметку; массовое создание (все пустые ссылки заметки) — отдельная команда с тем же порядком; пустой текст ссылки объектом не становится.
6. **Статусы в интерфейсе (раздел 5 контракта).** `draft` — виден с пометкой статуса (созданные из пустых ссылок объекты — `draft`); `accepted` — без пометок; `deprecated` — объект и ссылки остаются видимыми и действительными (`04-properties.md`, раздел 7; `06-relations.md`, раздел 4, правило 4), но тип исключается из списка выбора при создании из пустой ссылки и помечается в форме; перевод статуса — явное действие владельца; предупреждения и ошибки — правила валидации фазы 2.
7. **Граница контракта (ADR-008, U4; разделы 1 и 6 файла `10`).** Явно зафиксировано: это контракт поведения для фаз 4–5, а не спецификация UI-кода — не задаются компоненты, раскладка, стили, вызовы Obsidian API, порядок обработки событий; новые инварианты, свойства, отношения, метатипы и типы не вводятся; контракты реестров (`06-relations.md`, раздел 5; `08-field-expansion.md`, раздел 8) не дублируются; отклонение реализации — только через ADR (R-004); в «не входит» перечислены JSON Schema и валидация (фаза 2), примеры (фаза 3), поведение форм при развёртывании полей, визуальные свойства, синхронизация и конфликты.
8. **ADR-008: альтернативы.** А1 — где применять фильтрацию слоёв (4 варианта: принято «поиск и граф»; отклонены «все четыре поверхности», «только граф», «фильтрация по папкам вместо `layer`» — путь не часть идентичности, ADR-001). А2 — как хранить пресеты (4 варианта: принято «три канонических + пользовательские в настройках»; отклонены «пресеты как объекты системного слоя», «только три фиксированных», «пресет как заметка-конфигурация» — нарушение INV-04 и INV-12). А3 — подмена отображаемого имени (5 вариантов: принято «встроить в плагин»; отклонены «обязательная зависимость от FMT», «переименовывать файлы в `title`» — ломает INV-06 и ADR-001 R6, «не подменять, полагаться на alias», «отдельное свойство для отображаемого имени» — второй источник истины, DL-008). А4 — создание из пустых ссылок (5 вариантов: принято «по явной команде, тип по контексту»; отклонены «автоматически при сохранении», «всегда создавать `note`» — нарушение `target_type` (INV-17), «не создавать, только нормализовывать», «создавать со `status: accepted`» — против INV-10 и DL-011).
9. **ADR-008: последствия.** 5 положительных (поведение зафиксировано до кода — критерий успеха фазы 1; имена файлов остаются стабильными идентификаторами; создаваемый из ссылки объект сразу удовлетворяет INV-01…INV-12; контекст отношения используется как источник данных об интерфейсе — добавление отношения с единственным `target_type` не требует правки кода, принцип 2 `PROJECT_BRIEF.md`; модель не выросла) и 5 рисков с компенсациями (видимость UUID вне плагина; скрытый слой в поиске; вывод типа из изменённого `target_type`; массовые черновики; совпадения `title`).
