# Глоссарий

Единые определения терминов Second Brain PKB: одно понятие — один термин, одна формулировка. Глоссарий пополняется по мере появления артефактов; при расхождении формулировок приоритет у [`../metamodel/01-invariants.md`](../metamodel/01-invariants.md) и ADR.

## Правила пользования

- Термин — на английском (идентификаторы модели), определение — на русском (DL-001).
- Если термин введён, но ещё не нормативно закреплён, в колонке «Источник» стоит пометка `черновик`.
- Устаревшие термины не удаляются, а помечаются `[устаревший: iter-NNN]` с указанием замены (по образцу `RULES.md`).
- Новые термины добавляются вместе с артефактом, который их вводит; переопределение существующего термина — через DL и обновление этой таблицы.

## Термины

| Термин | Определение | Источник / связанные |
|---|---|---|
| **id** | Строковый идентификатор объекта в формате UUIDv7, каноническая строчная форма (36 символов). Выдаётся один раз, уникален в пределах хранилища, неизменяем. | INV-01…INV-03; DL-003, DL-006; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **Object** (объект) | Базовая единица модели: заметка в хранилище с обязательными свойствами `id`, `type`, `defined_by`, `title`, `aliases`, `layer`, `status`, `owner`. Тип, свойство, отношение, домен и фасет — тоже объекты. | [`../metamodel/01-invariants.md`](../metamodel/01-invariants.md); DL-003, DL-013 |
| **layer** (слой) | Обязательное свойство объекта со значением `system`, `classification` или `content`; определяет роль объекта в модели и согласовано со значением `type`. | INV-09; DL-010, DL-012; [ADR-002](../adr/ADR-002-three-layers.md) |
| **System layer** (системный слой) | Значение `layer: system`: объект описывает, как устроена модель, — встроенный метатип, определение типа (включая пользовательские), определение свойства или отношения, правило валидации, автоматизация. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Classification layer** (слой классификации) | Значение `layer: classification`: объект описывает, как объекты группируются, — домен, узел иерархической категории, фасет. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Content layer** (слой наполнения) | Значение `layer: content`: объект является знанием предметной области — экземпляром пользовательского типа. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Schema layer** (слой схемы) | `[устаревший: iter-002]` Значение `layer: schema` из двухслойной модели iter-001. Замена: **System layer** (`system`); в части экземпляров — **Content layer**. | [ADR-002](../adr/ADR-002-three-layers.md), DL-012 |
| **Instance layer** (слой экземпляров) | `[устаревший: iter-002]` Значение `layer: instance` из двухслойной модели iter-001. Замена: **Content layer** (`content`). | [ADR-002](../adr/ADR-002-three-layers.md), DL-012 |
| **Type** (тип) | Объект системного слоя с `type: type`, определяющий класс сущностей: какие свойства и отношения допустимы у его экземпляров. Обязательное свойство — `type_value`. | INV-04, INV-13; [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md) |
| **type_prefix** | Короткий префикс имени файла, производный от значения `type` по фиксированному правилу (нижний регистр, kebab-case, длина ≤ 16). Не задаётся вручную независимо от `type`. | INV-05; DL-007, DL-009; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **note filename** (имя файла заметки) | Имя файла объекта: `{{type_prefix}}_{{id}}` плюс расширение формата хранения (`.md`). Уникально в хранилище, не является частью идентичности объекта. | INV-06; DL-006 |
| **title** | Обязательное строковое свойство — читаемое имя сущности. Изменяемо; не влияет на `id`, имя файла и `type_value`. | INV-07; DL-008 |
| **aliases** | Список альтернативных имён объекта. Первый элемент всегда равен `title`; остальные — произвольные дополнительные имена. | INV-08; DL-008 |
| **defined_by** | Обязательное свойство любого объекта: `id` определения типа в системном слое, по которому объект создан. Для встроенного метатипа `type` равен собственному `id` (точка замыкания самоописания). | INV-12; DL-013; [ADR-002](../adr/ADR-002-three-layers.md) |
| **type_value** | Обязательное свойство определения типа (`type: type`): строка в ASCII kebab-case, которую экземпляры используют в свойстве `type`. Уникальна в хранилище, неизменяема после `accepted`. | INV-13; DL-013 |
| **Property** (свойство) | Объект системного слоя с `type: property`, определяющий характеристику объекта: `property_key`, `label` (= `title`), `value_type`, обязательность и область применения. Девять встроенных свойств зафиксированы реестром. | INV-16; DL-014; [`../metamodel/04-properties-relations.md`](../metamodel/04-properties-relations.md) |
| **Relation** (отношение) | Объект системного слоя с `type: relation`, определяющий связь между объектами: `relation_key`, `source_type`, `target_type`, `cardinality`. Значение хранится в объекте-источнике в канонической форме ссылки. Четыре встроенных отношения классификации зафиксированы реестром. | INV-17; DL-014; [`../metamodel/04-properties-relations.md`](../metamodel/04-properties-relations.md) |
| **Domain** (домен) | Объект слоя классификации с `type: domain`: крупная предметная область, верхний уровень группировки без иерархии; граница для категорий и область видимости фасетов. | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Hierarchical category** (иерархическая категория) | Объект слоя классификации с `type: hierarchical-category`: узел дерева категорий внутри домена; иерархия задаётся отношением «родитель — потомок». Канонический идентификатор зафиксирован DL-012. | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010, DL-012 |
| **Taxonomy** (таксономия) | `[устаревший: iter-002]` Черновой термин iter-001 для иерархической классификации. Замена: **Hierarchical category** (`hierarchical-category`). | DL-012 |
| **Facet** (фасет) | Объект слоя классификации с `type: facet`: независимое измерение классификации с равноправными значениями; комбинируется с другими фасетами без иерархии. Примеры: `Формат`, `Год`, `Статус проработки`. Значения фасета — отдельные объекты (**Facet value**). | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010, DL-016 |
| **Automation** (автоматизация) | Объект системного слоя с `type: automation`, описывающий правило автоматического действия (триггер → действие) над объектами хранилища. | [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md); черновик (детализация не выполнялась в iter-003) |
| **Validation rule** (правило валидации) | Объект системного слоя с `type: validation-rule`, описывающий проверку данных: условие, сообщение об ошибке, признак активности. Правила можно добавлять и отключать без изменения кода плагина. | черновик; машиночитаемая реализация — фаза 2 (`schema/`, `docs/validation/`) |
| **Status** (статус) | Обязательное свойство объекта со значением `draft` (черновик), `accepted` (принято, стабилен) или `deprecated` (выведен из эксплуатации). | INV-10; DL-011 |
| **deprecated** | Значение `status`: объект сохранён и ссылки на него действительны, но новые объекты и новые привязки по нему не создаются. Не означает удаление; не применяется к встроенным метатипам. Процедура по слоям — раздел 8 реестра свойств и отношений. | INV-10, INV-14; DL-011; [ADR-002](../adr/ADR-002-three-layers.md), [ADR-003](../adr/ADR-003-properties-links.md) |
| **Owner** (владелец) | Обязательное строковое свойство — ответственный за объект (человек или процесс). В персональной базе знаний по умолчанию `human`. | INV-11 |
| **Property key** (`property_key`) | Машинный идентификатор свойства: ASCII-строка, уникальная в хранилище, неизменяемая после `accepted`. Под этим ключом значение свойства хранится в frontmatter заметки и в JSON Schema фазы 2. | INV-16; DL-014; [ADR-003](../adr/ADR-003-properties-links.md) |
| **Label** (метка) | Человекочитаемое имя свойства или отношения в интерфейсе. Правило модели: `label` = `title` объекта-определения; отдельное поле не вводится. | INV-16; DL-014 |
| **Relation key** (`relation_key`) | Машинный идентификатор отношения: ASCII-строка, уникальная в хранилище; одновременно ключ поля в frontmatter объекта-источника, где хранится значение отношения. | INV-17; DL-014 |
| **Facet value** (значение фасета) | Объект слоя классификации с `type: facet-value`: конкретное значение фасета (`Книга`, `2026`, `Осмысленное`). Имеет ключ `facet` — каноническую ссылку на объект фасета. | [`../metamodel/04-properties-relations.md`](../metamodel/04-properties-relations.md); DL-016 |
| **Canonical internal link** (каноническая внутренняя ссылка) | Единственная допустимая форма ссылки на объект: `[[{{type_prefix}}_{{id}}|{{title}}]]`. Плагин создаёт только такие ссылки и нормализует остальные; исключение — `defined_by` (UUID строкой). | INV-15; DL-015; [ADR-003](../adr/ADR-003-properties-links.md) |
| **Value type** (тип значения) | Поле определения свойства или отношения: `string`, `uuid`, `list<string>`, `enum`, `link`, `boolean`, `number`, `date`. Используется при переносе реестра в JSON Schema (фаза 2). | [`../metamodel/04-properties-relations.md`](../metamodel/04-properties-relations.md); DL-014 |
| **Cardinality** (кратность) | Поле определения отношения: `0..1`, `1..1`, `0..*`, `1..*`. Контролируется правилом валидации. | [`../metamodel/04-properties-relations.md`](../metamodel/04-properties-relations.md); DL-014 |
| **UUIDv7** | Формат `id` проекта (RFC 9562): 128-битный идентификатор с меткой времени Unix в миллисекундах, лексикографически сортируемый в канонической форме. | INV-01; DL-006; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **Vault** (хранилище) | Каталог Obsidian с базой знаний; область уникальности `id`, имён файлов и `type_value`. | INV-02, INV-06, INV-13 |
| **Built-in metatype** (встроенный метатип) | Один из девяти объектов системного слоя, присутствующих в хранилище с момента инициализации и замыкающих самоописание модели: `type`, `property`, `relation`, `automation`, `validation-rule`, `domain`, `hierarchical-category`, `facet`, `facet-value`. Фиксированные `id` — в реестре. | INV-14; [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md); DL-010, DL-012, DL-016 |
