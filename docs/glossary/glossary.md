# Глоссарий

Единые определения терминов Second Brain PKB: одно понятие — один термин, одна формулировка. Глоссарий пополняется по мере появления артефактов; при расхождении формулировок приоритет у [`../metamodel/01-invariants.md`](../metamodel/01-invariants.md) и ADR.

## Правила пользования

- Термин — на английском (идентификаторы модели), определение — на русском (DL-001).
- Если термин введён, но ещё не нормативно закреплён, в колонке «Источник» стоит пометка `черновик`.
- Устаревшие термины не удаляются, а помечаются `[устаревший: iter-NNN]` с указанием замены (по образцу `RULES.md`).
- Новые термины добавляются вместе с артефактом, который их вводит; переопределение существующего термина — через DL и обновление этой таблицы.

## Термины

| Термин | Определение | Источник / связанные |
|---|---|---|
| **id** | Строковый идентификатор объекта в формате UUIDv7, каноническая строчная форма (36 символов). Выдаётся один раз, уникален в пределах хранилища, неизменяем. | INV-01…INV-03; DL-003, DL-006; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **Object** (объект) | Базовая единица модели: заметка в хранилище с обязательными свойствами `id`, `type`, `defined_by`, `title`, `aliases`, `layer`, `status`, `owner`. Тип, свойство, отношение, домен и фасет — тоже объекты. | [`../metamodel/01-invariants.md`](../metamodel/01-invariants.md); DL-003, DL-013 |
| **layer** (слой) | Обязательное свойство объекта со значением `system`, `classification` или `content`; определяет роль объекта в модели и согласовано со значением `type`. | INV-09; DL-010, DL-012; [ADR-002](../adr/ADR-002-three-layers.md) |
| **System layer** (системный слой) | Значение `layer: system`: объект описывает, как устроена модель, — встроенный метатип, определение типа (включая пользовательские), определение свойства или отношения, правило валидации, автоматизация. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Classification layer** (слой классификации) | Значение `layer: classification`: объект описывает, как объекты группируются, — домен, узел иерархической категории, фасет. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Content layer** (слой наполнения) | Значение `layer: content`: объект является знанием предметной области — экземпляром пользовательского типа. | INV-09; [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Schema layer** (слой схемы) | `[устаревший: iter-002]` Значение `layer: schema` из двухслойной модели iter-001. Замена: **System layer** (`system`); в части экземпляров — **Content layer**. | [ADR-002](../adr/ADR-002-three-layers.md), DL-012 |
| **Instance layer** (слой экземпляров) | `[устаревший: iter-002]` Значение `layer: instance` из двухслойной модели iter-001. Замена: **Content layer** (`content`). | [ADR-002](../adr/ADR-002-three-layers.md), DL-012 |
| **Type** (тип) | Объект системного слоя с `type: type`, определяющий класс сущностей: какие свойства и отношения допустимы у его экземпляров. Обязательное свойство — `type_value`; дополнительно — `extends`, `excludes`, `field_order` (**Type inheritance**). `label` типа равен его `title`. | INV-04, INV-13, INV-18…INV-20, INV-22; [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md), [`../metamodel/05-core-types.md`](../metamodel/05-core-types.md) |
| **type_prefix** | Короткий префикс имени файла, производный от значения `type` по фиксированному правилу (нижний регистр, kebab-case, длина ≤ 16). Не задаётся вручную независимо от `type`. | INV-05; DL-007, DL-009; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **note filename** (имя файла заметки) | Имя файла объекта: `{{type_prefix}}_{{id}}` плюс расширение формата хранения (`.md`). Уникально в хранилище, не является частью идентичности объекта. | INV-06; DL-006 |
| **title** | Обязательное строковое свойство — читаемое имя сущности. Изменяемо; не влияет на `id`, имя файла и `type_value`. | INV-07; DL-008 |
| **aliases** | Список альтернативных имён объекта. Первый элемент всегда равен `title`; остальные — произвольные дополнительные имена. | INV-08; DL-008 |
| **defined_by** | Обязательное свойство любого объекта: `id` определения типа в системном слое, по которому объект создан. Для встроенного метатипа `type` равен собственному `id` (точка замыкания самоописания). | INV-12; DL-013; [ADR-002](../adr/ADR-002-three-layers.md) |
| **type_value** | Обязательное свойство определения типа (`type: type`): строка в ASCII kebab-case, которую экземпляры используют в свойстве `type`. Уникальна в хранилище, неизменяема после `accepted`. | INV-13; DL-013 |
| **Property** (свойство) | Объект системного слоя с `type: property`, определяющий характеристику объекта: `property_key`, `label` (= `title`), `value_type`, обязательность и область применения. Девять встроенных свойств и двадцать три свойства ядра зафиксированы реестрами. | INV-16; DL-014, DL-026; [`../metamodel/04-properties.md`](../metamodel/04-properties.md), [`../metamodel/07-core-properties.md`](../metamodel/07-core-properties.md) |
| **Relation** (отношение) | Объект системного слоя с `type: relation`, определяющий связь между объектами: `relation_key`, `source_type`, `target_type`, `cardinality`. Значение хранится в объекте-источнике в канонической форме ссылки. Реестром зафиксированы четыре отношения классификации и четырнадцать отношений ядра (**Core relations**). | INV-17; DL-014, DL-020, DL-025; [`../metamodel/06-relations.md`](../metamodel/06-relations.md) |
| **Domain** (домен) | Объект слоя классификации с `type: domain`: крупная предметная область, верхний уровень группировки без иерархии; граница для категорий и область видимости фасетов. | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010 |
| **Hierarchical category** (иерархическая категория) | Объект слоя классификации с `type: hierarchical-category`: узел дерева категорий внутри домена; иерархия задаётся отношением «родитель — потомок». Канонический идентификатор зафиксирован DL-012. | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010, DL-012 |
| **Taxonomy** (таксономия) | `[устаревший: iter-002]` Черновой термин iter-001 для иерархической классификации. Замена: **Hierarchical category** (`hierarchical-category`). | DL-012 |
| **Facet** (фасет) | Объект слоя классификации с `type: facet`: независимое измерение классификации с равноправными значениями; комбинируется с другими фасетами без иерархии. Примеры: `Формат`, `Год`, `Статус проработки`. Значения фасета — отдельные объекты (**Facet value**). | [`../metamodel/02-layers.md`](../metamodel/02-layers.md); DL-010, DL-016 |
| **Automation** (автоматизация) | Объект системного слоя с `type: automation`, описывающий правило автоматического действия (триггер → действие) над объектами хранилища. | [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md); черновик (детализация не выполнялась в iter-003) |
| **Validation rule** (правило валидации) | Объект системного слоя с `type: validation-rule`, описывающий проверку данных: восемь обязательных свойств плюс служебные ключи **Rule key**, **Checked invariants**, **Rule severity**, **Rule scope**, `condition` (условие и алгоритм) и `message` (текст сообщения владельцу). Правила можно добавлять и отключать без изменения кода плагина: отключение — перевод в `deprecated`, в `draft` и `deprecated` правило не применяется. Служебные ключи зарегистрированы в реестре свойств, форма объекта выражена схемой `system-definitions.json` (пятая ветвь `oneOf`). Первая волна — восемь правил, вторая — шесть. | DL-038…DL-041; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S5); [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 5; [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), [`../validation/01-first-wave-rules.md`](../validation/01-first-wave-rules.md), [`../validation/02-second-wave-rules.md`](../validation/02-second-wave-rules.md) |
| **Status** (статус) | Обязательное свойство объекта со значением `draft` (черновик), `accepted` (принято, стабилен) или `deprecated` (выведен из эксплуатации). | INV-10; DL-011 |
| **deprecated** | Значение `status`: объект сохранён и ссылки на него действительны, но новые объекты и новые привязки по нему не создаются. Не означает удаление; не применяется к встроенным метатипам. Процедура по слоям — [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 7. | INV-10, INV-14; DL-011; [ADR-002](../adr/ADR-002-three-layers.md), [ADR-003](../adr/ADR-003-properties-links.md) |
| **Owner** (владелец) | Обязательное строковое свойство — ответственный за объект (человек или процесс). В персональной базе знаний по умолчанию `human`. | INV-11 |
| **Property key** (`property_key`) | Машинный идентификатор свойства: ASCII-строка, уникальная в хранилище, неизменяемая после `accepted`. Под этим ключом значение свойства хранится в frontmatter заметки и в JSON Schema фазы 2. | INV-16; DL-014; [ADR-003](../adr/ADR-003-properties-links.md) |
| **Label** (метка) | Человекочитаемое имя определения системного слоя (типа, свойства, отношения, правила валидации, автоматизации) в интерфейсе. Правило модели: `label` = `title` объекта-определения; отдельное поле не вводится. `key` определения отображается как индикатор, а не как имя. | INV-16, INV-22; DL-014, DL-021; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **Relation key** (`relation_key`) | Машинный идентификатор отношения: ASCII-строка, уникальная в хранилище; одновременно ключ поля в frontmatter объекта-источника, где хранится значение отношения. | INV-17; DL-014 |
| **Facet value** (значение фасета) | Объект слоя классификации с `type: facet-value`: конкретное значение фасета (`Книга`, `2026`, `Осмысленное`). Имеет ключ `facet` — каноническую ссылку на объект фасета. | [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 6; DL-016 |
| **Canonical internal link** (каноническая внутренняя ссылка) | Единственная допустимая форма ссылки на объект: `[[{{type_prefix}}_{{id}}\|{{title}}]]`. Плагин создаёт только такие ссылки и нормализует остальные; исключение — `defined_by` (UUID строкой). | INV-15; DL-015; [ADR-003](../adr/ADR-003-properties-links.md) |
| **Value type** (тип значения) | Поле определения свойства или отношения; принимает одно из 14 канонических значений: `string`, `text`, `number`, `boolean`, `date`, `datetime`, `enum`, `list<string>`, `list<enum>`, `link`, `list<link>`, `uuid`, `media`, `list<media>`. Набор закрыт, значение неизменяемо после `accepted`; используется при переносе реестра в JSON Schema (фаза 2). | INV-21; [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 2; DL-018, DL-023 |
| **Cardinality** (кратность) | Поле определения отношения: `0..1`, `1..1`, `0..*`, `1..*`. Контролируется правилом валидации. | [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 5; [`../metamodel/06-relations.md`](../metamodel/06-relations.md), раздел 1; DL-014 |
| **Type inheritance** (наследование типов) | Механизм переиспользования набора полей: определение типа-потомка наследует свойства и отношения предка через `extends`; исключает их через `excludes`; конфликт объявлений решается правилом **Nearest wins**. Наследование одиночное и линейное, цепочка ациклична; встроенные метатипы не участвуют. | INV-18…INV-20; DL-017; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **extends** | Служебный ключ определения типа (`type: type`), кратность `0..1`, `value_type: link`: каноническая ссылка на родительское определение типа. У определения в `accepted` не меняется. | INV-18; DL-017; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **excludes** | Служебный ключ определения типа: список `property_key` и `relation_key`, исключённых из эффективного набора полей этого типа и всех его потомков. Универсальные обязательные свойства не исключаются. | INV-19; DL-017; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **Field order** (порядок представления полей) | Детерминированный порядок полей в формах плагина и в JSON Schema: универсальные обязательные свойства → унаследованные поля от корня к листу → собственные поля в порядке `field_order`. | INV-20; DL-017; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **Effective field set** (эффективный набор полей) | Множество ключей свойств и отношений, применимых к объекту: объявления всех типов цепочки `extends` за вычетом `excludes` плюс объединение полей активных правил развёртывания. Вычисляется плагином или валидатором, в данных не хранится. | INV-20, INV-26; DL-017, DL-028 |
| **Nearest wins** | Правило разрешения конфликтов наследования: если ключ объявлен на нескольких уровнях цепочки `extends`, он принадлежит ближайшему к листу уровню — это определяет принадлежность поля типу и его позицию в порядке представления. Параметры поля (`value_type`, `required`, `cardinality`) на уровне типа не переопределяются. | INV-20; DL-017; [ADR-004](../adr/ADR-004-type-inheritance.md) |
| **Core types** (ядро типов) | Рекомендуемый стартовый набор из 29 определений типов слоя наполнения в пяти группах: Знания, Контекст, Медиа, Коллекции, Действия. Фиксированных `id` не имеет; владелец может расширять, переименовывать и переводить в `deprecated`. | [`../metamodel/05-core-types.md`](../metamodel/05-core-types.md); DL-019 |
| **Core type group** (группа ядра) | Организационная разметка реестра ядра типов: Знания (`note` и потомки), Контекст (`person`, `organization`, `place`, `event`, `project`, `area`), Медиа (`source`, `file` и потомки, включая `film`, `track`, `chapter`, обёртку `image`), Коллекции (`film-series`, `album`, `gallery`), Действия (`task`, `goal`, `decision`, `meeting` и потомки). В данных не хранится; наследование может пересекать группы. | [`../metamodel/05-core-types.md`](../metamodel/05-core-types.md); DL-019, DL-025 |
| **Core relations** (отношения ядра) | Четырнадцать отношений для экземпляров типов ядра: `author`, `about`, `part-of`, `participant`, `derived-from`, `supports`, `blocks`, `located-in`, `member-of`, `references`, `contradicts`, `chapter-of`, `part-of-collection`, `narrator`. Определения имеют фиксированные `id`; обратные направления вычисляются плагином и не хранятся. | [`../metamodel/06-relations.md`](../metamodel/06-relations.md), раздел 3; DL-020, DL-025, DL-027 |
| **Enum values** (`enum_values`) | Служебный ключ определения свойства или отношения: непустой список допустимых значений при `value_type: enum` или `list<enum>`. Открытые наборы значений моделируются фасетом, а не перечислением. | INV-21; DL-018 |
| **UUIDv7** | Формат `id` проекта (RFC 9562): 128-битный идентификатор с меткой времени Unix в миллисекундах, лексикографически сортируемый в канонической форме. | INV-01; DL-006; [ADR-001](../adr/ADR-001-identity-and-typing.md) |
| **Vault** (хранилище) | Каталог Obsidian с базой знаний; область уникальности `id`, имён файлов и `type_value`. | INV-02, INV-06, INV-13 |
| **Media** (`media`) | Значение `value_type`: каноническая ссылка на **Image wrapper** — объект `type: image`. От `link` отличается семантикой цели, а не формой; в интерфейсе отображается превью, `list<media>` — галереей миниатюр. Визуальные свойства ядра `cover`, `poster`, `photo` (`media`) и `artwork` (`list<media>`). | INV-21, INV-23; DL-023; [ADR-005](../adr/ADR-005-core-extension-and-split.md) |
| **Image wrapper** (обёртка изображения) | Объект `type: image` — потомок `file`: метаданные изображения плюс обязательный ключ **Attachment**. Делает картинку частью базы (её можно связать отношениями, сослаться на неё из визуального свойства); сам графический файл объектом модели не является. | INV-24; DL-024; [`../metamodel/05-core-types.md`](../metamodel/05-core-types.md), раздел 4.2 |
| **Attachment** (вложение) | Свойство ядра `attachment` (`value_type: string`): путь к вложению Obsidian относительно хранилища. Обязательно для обёртки `image`, для остальных типов области применения — по желанию. Не является ссылкой и не создаёт объект модели. | INV-24; DL-024; [`../metamodel/07-core-properties.md`](../metamodel/07-core-properties.md), раздел 3 |
| **Collection** (коллекция) | Тип ядра группы «Коллекции»: `film-series` (серия фильмов), `album` (альбом), `gallery` (галерея). | **Chapter** (глава) | Тип ядра `chapter`, потомок `source`: структурная часть книги или иного источника, объект цитирования. Привязка к книге — отношение `chapter-of` (`1..1`) со стороны главы; порядок — `position`. Книга-агрегатор глав — одна из трёх ролей `book`. | DL-025; [`../metamodel/05-core-types.md`](../metamodel/05-core-types.md), раздел 4.1 |
| **Core properties** (свойства ядра) | Двадцать три определения свойств с фиксированными `id`, рекомендуемых для экземпляров типов ядра: четыре визуальных (`cover`, `poster`, `photo`, `artwork`), одиннадцать типовых (`url`, `isbn`, `published`, `year`, `duration`, `date`, `due`, `completed`, `attachment`, `position`, `page`), три триггера (`occupation`, `format`, `creation-method`) и пять разворачиваемых полей (`specialization`, `model`, `prompt`, `seed`, `page-count`). Все — `required: conditional`; встроенными не являются и INV-14 не защищены. | DL-026, DL-027; [`../metamodel/07-core-properties.md`](../metamodel/07-core-properties.md) |
| **Position** (позиция) | Свойство ядра `position` (`value_type: number`): порядковый номер элемента внутри книги или коллекции, нумерация с 1. Хранится у элемента, а не списком у книги или коллекции. | DL-025, DL-026; [`../metamodel/07-core-properties.md`](../metamodel/07-core-properties.md), раздел 3 |
| **Built-in metatype** (встроенный метатип) | Один из десяти объектов системного слоя, присутствующих в хранилище с момента инициализации и замыкающих самоописание модели: `type`, `property`, `relation`, `automation`, `validation-rule`, `field-expansion`, `domain`, `hierarchical-category`, `facet`, `facet-value`. Фиксированные `id` — в реестре. | INV-14; [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md); DL-010, DL-012, DL-016, DL-029 |
| **Field expansion** (развёртывание полей) | Механизм триггерных свойств: значение свойства-триггера определяет, какие дополнительные поля входят в эффективный набор полей объекта. Правила механизма — объекты системного слоя, а не часть определения типа; результат — представление и состав полей, а не изменение данных. | [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md); INV-25…INV-27; DL-027; ADR-006 |
| **Trigger property** (свойство-триггер) | Свойство с `value_type: enum` или `list<enum>`, значение которого сопоставляется с `trigger_values` правил развёртывания. В ядре — `occupation`, `format`, `creation-method`; сопоставление по точному совпадению строки из `enum_values`. | [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 3; INV-25; DL-027 |
| **Expansion rule** (правило развёртывания) | Объект системного слоя `type: field-expansion`: при каких значениях триггера (`trigger_values`) и у каких типов (`applies_to_type`) к эффективному набору полей добавляются `adds_properties` и `adds_relations`. `id` правила не фиксируется реестром и выдаётся при создании; правило в `draft` или `deprecated` не применяется. Отличается от `validation rule`: не проверяет данные, а определяет состав полей. | [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 2; INV-25; DL-027, DL-029 |
| **Union** (`mode: union`) | Единственный режим развёртывания в v1: результат — объединение множеств полей всех активных правил. Идемпотентно и коммутативно, поэтому порядок правил и дубликаты ключей на состав полей не влияют; режимы `first-match` и `override` не определены. | [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 5; INV-26; DL-028 |
| **Inactive field** (неактивное поле) | Поле, значение которого присутствует в frontmatter, но ни одно активное правило развёртывания его не добавляет (триггер изменён или удалён, правило отключено). Значение сохраняется, интерфейс скрывает поле, валидатор фазы 2 выдаёт предупреждение; очистка — только явная команда владельца. | INV-27; DL-028; [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 7 |
| **Layer visibility** (видимость слоя) | Фильтрация представления по значению `layer`: три глобальных тумблера (`system`, `classification`, `content`) и три канонических пресета. Действует в поиске и графе; проводник и quick switcher показывают все объекты. Данные, разрешение ссылок и валидация от видимости не зависят. По умолчанию `content` и `classification` видимы, `system` скрыт. | INV-09; DL-031; [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), раздел 2 |
| **Layer visibility preset** (пресет видимости) | Именованная комбинация трёх тумблеров видимости, переключаемая одной командой: «Только знания», «Модель», «Всё». Пользовательские пресеты хранятся в настройках плагина; объектом модели пресет не является. | DL-031; [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), раздел 2.2 |
| **Display title** (отображаемое имя) | Значение `title` объекта, показываемое вместо имени файла во всех списках и заголовках: проводник, вкладки, заголовок заметки, поиск, quick switcher, подписи узлов графа, панели ссылок, предпросмотр. Файл не переименовывается, имя остаётся `{{type_prefix}}_{{id}}.md`; подмена встроена в плагин и не требует сторонних плагинов. При совпадении `title` рядом показывается индикатор типа. | INV-06, INV-07, INV-08; ADR-001 (R6); DL-021, DL-032; [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), раздел 3 |
| **Unresolved link** (пустая ссылка) | Внутренняя ссылка `[[…]]`, цель которой не разрешается в существующий файл хранилища. В модели объект по такой ссылке отсутствует; создание объекта выполняется явной командой владельца (Empty link creation), а не автоматически. | INV-15; DL-033; [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), раздел 4.1 |
| **Empty link creation** (создание из пустой ссылки) | Создание объекта модели по явной команде из пустой ссылки: тип выбирается по контексту (в теле — из принятых определений типов; в значении свойства или отношения — по допустимому `target_type`, при единственном — без запроса), объект получает `id`, имя файла, `defined_by`, `title` из текста ссылки, `layer` по INV-09, `status: draft`, а ссылка нормализуется к канонической форме. | INV-01…INV-12, INV-15, INV-17; DL-011, DL-033; [`../metamodel/10-plugin-ux-contracts.md`](../metamodel/10-plugin-ux-contracts.md), разделы 4.2–4.4 |
| **JSON Schema** (схема) | Машиночитаемое выражение формы объекта: документ JSON Schema версии 2020-12 в каталоге `schema/`. `$id` — относительное имя файла, `$ref` — по именам файлов и указателям `#/$defs/…`; один файл — один класс объектов (`object.json`, `system-definitions.json`, `media.json`), выбор схемы — по значению `type`. Каталог автономен: внешних URL, кроме идентификатора версии, нет. | DL-037; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S3, S4, А1, А2) |
| **Schema instance** (экземпляр схемы) | JSON-документ, полученный из YAML frontmatter одной заметки: ключи соответствуют `property_key` и `relation_key`, значения — форме по `value_type`. Тело заметки, имя файла и путь в экземпляр не входят; `date` и `datetime` остаются строками ISO 8601; `additionalProperties` не запрещён, поскольку состав полей экземпляра вычисляется по типу и активным правилам развёртывания. | DL-036, DL-037; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S2, А5); INV-06, INV-20, INV-26 |
| **Schema–rule boundary** (граница «схема — правило») | Разделение контроля фазы 2: схема проверяет форму одного объекта (присутствие ключей, допустимость значения, условные зависимости внутри объекта), правило валидации — всё, что требует имени файла, другого объекта, множества объектов или вычисления. Проверка, выразимая схемой, в правилах не дублируется; правило вправе ссылаться на тот же инвариант, если добавляет межобъектную часть. | DL-036; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S1); [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), раздел 2 |
| **Rule key** (`rule_key`) | Машинный идентификатор правила валидации: ASCII-строка в kebab-case, уникальная в пределах хранилища; одновременно ключ правила в реестре `docs/validation/`. Значение воспроизводится в `aliases[1]` объекта правила — по образцу определений свойств. | DL-038; INV-16, INV-22; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S5) |
| **Checked invariants** (`checks`) | Служебный ключ правила валидации: непустой список идентификаторов нормативных ограничений, которые правило контролирует. Допустимые формы: инвариант (`INV-02`), запись журнала решений (`DL-038`) и указатель пункта реестра (`06-relations.md#2.1`) — последние две для ограничений, у которых нет инварианта; если инвариант существует, он указывается обязательно. Даёт машиночитаемую связь правила с реестром инвариантов: один инвариант может контролироваться и схемой, и правилом. Форму идентификаторов контролирует схема. | DL-038, DL-040; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S1, S5); [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), раздел 3 |
| **Rule severity** (`severity`) | Исход срабатывания правила валидации: `error` — нарушен инвариант, объект невалиден и не принимается как источник определений; `warning` — данные сохраняются, владелец уведомляется. Третьего уровня нет; перевод правила между уровнями — изменение семантики модели и выполняется через DL. | DL-038; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S5, А4); [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), раздел 4 |
| **Rule scope** (`applies_to`) | Область применения правила валидации: `"*"` (все объекты) или список `type_value` определений типов — как у определений свойств. | DL-038; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S5); [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 5 |
| **First wave** (первая волна) | Состав артефактов фазы 2, созданный в iter-009: три схемы (`object.json`, `system-definitions.json`, `media.json`) и восемь правил валидации, все с `severity: error`. Ограничение итерации — не раздувать первую волну; прочее перечислено как кандидаты второй волны. | DL-036…DL-039; [ADR-009](../adr/ADR-009-phase2-schemas.md) (S4, S6); [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), разделы 6.1 и 7 |
| **Second wave** (вторая волна) | Состав артефактов фазы 2, созданный в iter-010: шесть правил валидации — три межобъектные проверки с `severity: error` (`link-target-exists`, `unique-machine-keys`, `relation-acyclic`) и три предупреждения (`inactive-field-value`, `extends-depth`, `deprecated-link-target`), — регистрация служебных ключей `validation-rule` в реестре свойств и ветвь схемы объекта правила. Нумерация правил в реестре сквозная (9…14). | DL-040, DL-041; [`../validation/02-second-wave-rules.md`](../validation/02-second-wave-rules.md), [`../validation/00-validation-rules.md`](../validation/00-validation-rules.md), раздел 6.2 |
| **Orphaned value** (осиротевшее значение) | Значение развёрнутого поля, сохранённое во frontmatter после того, как поле стало неактивным из-за смены или удаления значения свойства-триггера. Данные не удаляются и не изменяются автоматически, поле скрывается из формы представления, а непустое значение помечается предупреждением правила `inactive-field-value`; очистка — явное действие владельца. | INV-27; DL-028, DL-040; [`../metamodel/08-field-expansion.md`](../metamodel/08-field-expansion.md), раздел 7 |
