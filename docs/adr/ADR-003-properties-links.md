# ADR-003: Ключ и метка свойства, каноническая внутренняя ссылка

Архитектурное решение о паре **key / label** для свойств модели, о канонической форме внутренней ссылки `[[{{type_prefix}}_{{id}}|{{title}}]]` и о представлении значений фасета отдельными объектами.

## Контекст

К iter-003 метамодель фиксирует объекты, три слоя и восемь (с iter-003 — девять) встроенных метатипов, но не фиксирует, как свойства и связи представляются в заметке и в интерфейсе. Без этого нельзя ни реализовать плагин, ни перенести инварианты в JSON Schema (фаза 2). Три открытых вопроса:

1. **Машинное имя против человеческого.** Ключ свойства участвует в данных (frontmatter, схема, правила валидации) и обязан быть стабильным и ASCII-совместимым. Имя, которое видит человек, обязано быть читаемым и может меняться. Одно поле не может выполнять обе роли: переименование свойства для интерфейса меняло бы данные всех заметок.
2. **Форма ссылки.** Obsidian допускает ссылку по имени файла, по `title` и по `aliases`. Ссылка по `title` ломается при переименовании и неоднозначна при одинаковых `title` (уникальность `title` не требуется — ADR-001, R6). Ссылка по имени файла стабильна, но нечитаема. Человек зафиксировал требование: плагин нормализует ссылки в форму `[[имя_файла|title]]`.
3. **Значения фасетов.** Фасет объявлен метатипом в iter-002, но форма его значений не выбрана: строки в перечислении или отдельные объекты. От выбора зависит, можно ли значение переименовать, перевести в `deprecated` и показать в графе.

Ограничения: офлайн-работа; идентификаторы на английском, документация на русском (DL-001); `id` неизменяем (DL-006); имя файла = `{{type_prefix}}_{{id}}` (DL-006); `title` обязателен и дублируется в `aliases[0]` (DL-008); расширение модели без правки кода плагина (PROJECT_BRIEF).

## Решение

### P1. Свойство имеет `property_key` и `label`

- Каждое свойство — объект системного слоя `type: property` с обязательным `property_key`: машинный идентификатор, ASCII, уникален в хранилище, неизменяем после `accepted`.
- **`label` = `title`** объекта-свойства. Отдельное поле `label` не вводится: `title` уже обязателен (INV-07), уже дублируется в `aliases[0]` (INV-08) и уже изменяем без последствий для данных.
- `aliases[1] = property_key` — свойство находится в поиске и по русскому имени, и по машинному ключу.
- Значение свойства хранится в frontmatter заметки под ключом `property_key`.

### P2. Отношение хранится в источнике как каноническая ссылка

- Каждое отношение — объект системного слоя `type: relation` с обязательным `relation_key`, `source_type`, `target_type`, `cardinality`.
- Значение отношения хранится в объекте-источнике, в frontmatter под ключом `relation_key`, в канонической форме ссылки (P3). Множественные значения — список YAML.
- Обратное отношение по умолчанию не хранится и вычисляется плагином; `inverse_key` заполняется только если обратная связь хранится явно.

### P3. Каноническая форма внутренней ссылки

```
[[{{type_prefix}}_{{id}}|{{title}}]]
```

- Цель — имя файла объекта без пути и расширения (INV-06): стабильна, потому что `id` неизменяем (INV-03).
- Alias — значение `title` цели: читаем и обновляется плагином при переименовании.
- Плагин создаёт только канонические ссылки и нормализует неканонические (`[[имя_файла]]`, `[[title]]`, `[[путь/имя_файла]]`) к канонической форме.
- Исключение: `defined_by` хранит UUID строкой, а не ссылкой (INV-12) — значение нужно для машинной проверки согласованности типа, а не для навигации.

### P4. Значение фасета — объект `facet-value`

- Вводится девятый встроенный метатип `facet-value` (фиксированный `id` — в [`../metamodel/03-builtin-types.md`](../metamodel/03-builtin-types.md), DL-016).
- Следствие для ADR-002 (S4): множество значений `type`, требующих `layer: classification`, пополняется значением `facet-value` — {`domain`, `hierarchical-category`, `facet`, `facet-value`}. Правило соответствия слоя и типа обновлено в INV-09 и [`../metamodel/02-layers.md`](../metamodel/02-layers.md); прочие формулировки ADR-002 не пересматриваются.
- Значение фасета — объект слоя `classification` с `type: facet-value`, обязательным ключом `facet` (каноническая ссылка на объект фасета, кратность `1..1`), `title` (например, `Книга`) и стандартным набором свойств.
- Привязка знания к значению — отношение `object-facet-value` (P2).

### P5. Поведение при `deprecated`

Уточнение DL-011 фиксируется в [`../metamodel/04-properties.md`](../metamodel/04-properties.md), раздел 7: объект сохраняется, ссылки действительны, новые объекты и новые привязки не создаются, миграция экземпляров типа выполняется только через создание новых объектов (без правки `id`, `type` и имени файла существующих).

## Альтернативы

### А1. Способ задать машинное имя и человекочитаемое имя свойства

| Вариант | Оценка |
|---|---|
| **`property_key` + `label` = `title` (принято)** | Данные стабильны, интерфейс читаем, дублирование полей отсутствует, `aliases` дают поиск по обеим формам |
| Одно поле `title` как ключ | Отклонён: переименование свойства в интерфейсе меняло бы frontmatter всех заметок; кириллица в ключах YAML/JSON Schema нежелательна |
| Одно поле `key` как имя в интерфейсе | Отклонён: человек видит `defined_by` вместо «Определён типом»; противоречит требованию человека о label |
| Отдельное поле `label` помимо `title` | Отклонён: два изменяемых поля с одной ролью — источник рассинхронизации; `title` уже обязателен и уже отображается |
| `property_key` производен от `title` транслитерацией | Отклонён: неоднозначно для кириллицы, меняется при правке `title`, коллизии требуют ручного разрешения |

### А2. Форма внутренней ссылки

| Вариант | Оценка |
|---|---|
| **`[[{{type_prefix}}_{{id}}|{{title}}]]` (принято)** | Цель стабильна (имя файла), подпись читаема (`title`), нормализация автоматизируется; решение человека |
| `[[title]]` | Отклонён: `title` изменяем и не уникален (ADR-001, R6) — ссылки ломаются и становятся неоднозначными |
| `[[имя_файла]]` без alias | Отклонён: в тексте заметки виден UUID, читаемость нулевая; Obsidian не покажет человекочитаемое имя |
| `[[id]]` со скрытым разрешением через плагин | Отклонён: ссылка неработоспособна вне плагина (в веб-экспорте, в других редакторах, в поиске по файлам) |
| Markdown-ссылки `[title](путь/файл.md)` | Отклонён: зависят от пути, который не является частью идентичности (ADR-001); теряется граф Obsidian |
| Отдельное поле `links` со списком `id` | Отклонён: связи исчезают из графа Obsidian и из текста заметки; дублирует механизм ссылок |

### А3. Представление значений фасета

| Вариант | Оценка |
|---|---|
| **Объекты `facet-value` (принято)** | Значение имеет `id`, `title`, `status`, `aliases`; его можно переименовать, перевести в `deprecated`, показать в графе; привязка — стандартное отношение |
| Перечисление строк в объекте фасета | Отклонён: значения нельзя перевести в `deprecated` или переименовать без правки всех заметок; нет страницы значения, нечего показывать в графе |
| Свойство-тег в заметке (`format: book`) | Отклонён: теги живут вне модели, не имеют `defined_by`, не контролируются правилами валидации; противоречит принципу самоопределения |
| Таксономия значений фасета как иерархические категории | Отклонён: фасет объявлен независимым от иерархии измерением (ADR-002, S2); смешение механизмов разрушает различие категорий и фасетов |

## Последствия

**Положительные:**

- Данные и интерфейс развязаны: переименование свойства или отношения меняет только `title`, а не заметки.
- Ссылки стабильны и читаемы одновременно; переименование объекта не ломает входящие связи (правится только alias).
- Значения фасетов стали полноценными объектами модели: работают те же инварианты, статусы и ссылки.
- Реестр свойств и отношений переносится в JSON Schema фазы 2 почти без изменений: `property_key` → имя поля, `value_type` → тип, `required`/`applies_to` → ограничения, `cardinality` → ограничения списка.
- Контракт для плагина сформулирован без деталей реализации: можно использовать штатный виджет Obsidian или собственный UI.

**Отрицательные и риски:**

- Ссылка в канонической форме длинная: в тексте заметки виден UUID, если alias потерян (ручная правка, перенос текста). Компенсация: плагин нормализует ссылки (P3), alias восстанавливается из `title` цели.
- `defined_by` — исключение из канонической формы: два способа записи связи в одной модели. Компенсация: исключение единственное, зафиксировано в INV-12, INV-15 и разделе 4 реестра.
- Девятый встроенный метатип `facet-value` расширяет bootstrap: создавать нужно девять метатипов, девять свойств и четыре отношения. Компенсация: все `id` фиксированы реестрами, bootstrap выполняется один раз.
- Ключ `facet` у значений фасета — ещё один обязательный ключ вне реестра встроенных свойств (он относится к слою классификации). Компенсация: описан в разделе 7 реестра, будет перенесён в JSON Schema вместе с остальными.
- Нормализация ссылок плагином меняет текст заметок пользователя: требуется явная команда или сохранение заметки, а не фоновая правка всего хранилища. Компенсация: требование к плагину — нормализация только редактируемой заметки и по явной команде ([`../metamodel/06-relations.md`](../metamodel/06-relations.md), раздел 5, п. 2).
- Штатный виджет свойств Obsidian может не поддерживать отображение `label` и канонических ссылок; в этом случае нужен собственный UI. Реализация — фазы 4–5, вне scope фазы 1.

**Что фиксируется дополнительно:**

- DL-014 — пара `property_key` / `label` (= `title`), состав обязательных полей определений свойств и отношений.
- DL-015 — каноническая форма внутренней ссылки и обязанность плагина нормализовать ссылки; исключение для `defined_by`.
- DL-016 — значения фасета как объекты `facet-value`, новый встроенный метатип, ключ `facet`.
- Инварианты INV-15 (каноническая ссылка), INV-16 (`property_key`), INV-17 (`relation_key`) в [`../metamodel/01-invariants.md`](../metamodel/01-invariants.md).

**Для фазы 2 и плагина:**

- Фаза 2: `property_key` → имена полей JSON Schema; `value_type` → типы; `applies_to`/`required`/`cardinality` → ограничения; правила валидации для циклов в `parent`, согласованности `category-domain` и формы ссылок (INV-15).
- Фазы 4–5: bootstrap по трём реестрам (метатипы, свойства, отношения), нормализация ссылок, формы редактирования по `label`. Контракт для плагина — [`../metamodel/06-relations.md`](../metamodel/06-relations.md), раздел 5.
